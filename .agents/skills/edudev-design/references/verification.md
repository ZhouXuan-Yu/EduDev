# 验证与反例

## 验收层次

1. Skill结构：YAML、引用存在、无残留脚手架；仅证明可读取。
2. 代表样张：1366×768、1920×1080以及窄窗、150%缩放下查看；键盘、焦点、滚动、状态切换有证据。仅证明布局提案，不代表真实HeroUI或业务路径。
3. 正式页面：build/type、相关组件及原回归；真实Electron记录CSSOM/获胜选择器/来源/层、renderer错误、IME/草稿/流式/停止/恢复，按原runId核对工具与正文。
4. 教师视觉接受：用户审阅前后截图；不能以自动化通过替代。

开发任务的可追踪验收编号在 `docs/goal/UI_DESIGN_IMPLEMENTATION_V2.md`。报告每个编号的通过/失败/未测，不把离线 34 项（或后续增量）自动记为生产 AT。最终 HTML 检查报告读取当前 evidence/report.json，不沿用文档中的旧次数。

截图必须写明源码、native/CSS尺寸、DPR、数据根、场景和是否样张。对比Hover/Focus/Pressed、empty/loading/ready/running/completed/partial/failed/cancelled/retry、展开/收起；本产品仅浅色。只跑本轮相关检查，不为文档更改重复全业务付费验收。

## 从本轮否决截图派生的反例

| 情境 | 应作的决定 | 必须拒绝的捷径 |
| --- | --- | --- |
| 首页看起来满且卡片重复 | 输入优先、轻量入口、右栏按需 | 换三张更大更花的卡片 |
| 学生页入口多、列表找不到 | 先选学生，再上下文切换 | 删除错题/计划能力，或再套一层七卡片 |
| 设置文字太多 | 按重要性分层，保护权限提示 | 将全部隐私和错误提醒隐藏 |
| 组件样式被污染 | 查computed style与赢得层级，修应用边界 | vendor改色/全局important/叠一份CSS |
| 资料解析原文很长 | 默认概要，按来源展开对照 | 删除原始证据、丢失版本或伪造答案 |
| 需要“高级感” | 对齐、层级、清晰文字、真实任务 | 引入第二套UI库、3D、玻璃和装饰动画 |
| 主题样张已通过 | 逐页最小迁移并验证 | 批量覆盖全部组件token或宣称全项目已通过 |

这些是预期行为用例，当前未做独立模型行为评测；不得把表格行数当成测试通过数。对审批写入等既有失败，独立保留，不用布局修改宣称修复。
