# 视觉与组件边界

## 已确认的基线

中性白灰、无玻璃或装饰渐变，黑灰正文。强调色有语义，信息文字不能整页染蓝。应用界面约15px、正文约16px，中文无衬线；原文/Office预览保持文件字体。不要让每段文字都成为标题，也不要将主要内容缩小到辅助字号。

布局所有者提供一层内边距。分隔用对齐、空隙和必要细线；卡片只用于独立对象或可选择方案，不能为所有分组套卡片。无效空白与信息拥挤都须在真实内容下检查。

## 样张数值不是生产 Token

项目 `docs/design/system/review/review.css` 中带 `--review-` 前缀的数值仅用于布局审阅。当前提案：4/8px节奏、主区24–32px边距、正文行高1.7、左栏224px、阅读宽720px。色值、圆角、宽度和断点待样张接受及实际组件测量后校准，不直接覆盖 HeroUI 变量。密度要求按 CSS viewport 评估，记录 native尺寸、DPR和缩放，不能混称物理分辨率。

## HeroUI

- 使用官方 API、semantic variant 和原交互态；先核对本地实际版本与导入源，不把在线新版本 API 硬套旧源码。
- 官方公开网站/文档优先，MCP为附加核对；不可用时查 `D:/WorkProject/HeroUIPro/herouipro-v3/src`，不能因此停止或要求 PAT。
- 不改 vendor，不增加全局 !important，不用全局 button/input/h1规则改组件；不以新增 CSS 层掩盖旧污染。
- 区分应用外壳（布局/阅读字体）和组件内部（slot、状态、颜色、圆角）。应用样式类独立命名；严禁改变组件内部外观而未告知用户。
- 需要统一主题时先列出影响范围、获胜选择器、原厂对照和样张，经用户确认后单一主题源修改；不能逐页覆盖 Token。已批准的应用字号不是修改所有原厂控件字号的授权。
- 不增加图标库，沿既有 lucide-react；图标样式/大小与同类用途一致。仅信息文字不设置伪 Hover。
- 官方 CSS 顺序为 Tailwind→OSS→Pro；在本项目核对实际边界适配器和本地 vendor 加载，不盲加重复 CSS 导入。

## 交互态

Hover、Selected、Pressed、Keyboard focus可区分。图标按钮有可访问名称，提示不能只靠 Hover。常规披露150–200ms并尊重 reduced-motion；正文流式、文件预览不反复入场。不得为柔和视觉取消焦点轮廓或降低不可读文字对比。
