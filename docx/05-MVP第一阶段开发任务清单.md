# MVP 第一阶段开发任务清单

## 1. 第一阶段目标

跑通个人老师本地学生档案系统的最小闭环：

```text
创建学生 -> 添加学习记录 -> 上传附件 -> 本地保存 -> 时间线查看 -> 生成阶段复盘
```

第一阶段不接复杂 OCR，不接自动组卷，不做团队功能。

## 2. 推荐工程结构

```text
EduProject/
  apps/
    desktop/
      src/
        main/
        preload/
        renderer/
  python/
    omni_edu/
  docx/
  data/
    samples/
```

## 3. Sprint 0: 工程初始化

目标：

搭好能运行的桌面应用骨架。

任务：

- 初始化 Electron + Vite + React + TypeScript。
- 配置 ESLint 和 Prettier。
- 建立 Electron main/preload/renderer 边界。
- 建立安全 IPC 调用方式。
- 建立应用数据目录读取工具。
- 建立 SQLite 连接。

验收：

- `npm run dev` 能打开桌面窗口。
- Renderer 能通过 IPC 调用 Main。
- Main 能读写本地应用数据目录。

## 4. Sprint 1: 学生档案

目标：

完成学生档案 CRUD。

任务：

- 创建 SQLite 表 `students`。
- 实现新增学生。
- 实现编辑学生。
- 实现归档学生。
- 实现学生列表。
- 支持按姓名、年级、标签搜索。

界面：

- 左侧学生列表。
- 右侧学生详情。
- 新建学生按钮。
- 标签展示。

验收：

- 能创建 30 个学生档案。
- 关闭应用后再次打开，数据仍存在。

## 5. Sprint 2: 学习记录

目标：

支持给学生持续追加学习记录。

任务：

- 创建 SQLite 表 `learning_records`。
- 学生详情页增加“添加记录”入口。
- 支持记录类型选择。
- 支持科目选择。
- 支持标题和正文。
- 支持标签。
- 学生详情页展示时间线。

验收：

- 能给同一学生添加多条记录。
- 能按时间倒序展示。
- 能按记录类型筛选。

## 6. Sprint 3: 附件管理

目标：

支持给学习记录挂附件。

任务：

- 创建 SQLite 表 `attachments`。
- 建立学生本地目录。
- 导入附件时复制到学生目录。
- 记录附件路径、类型、大小。
- 支持打开附件所在位置。
- 支持图片缩略图。

验收：

- 能给一条记录添加多个附件。
- 大文件不写入数据库。
- 删除记录时不立即物理删除附件，先保留可恢复策略。

## 7. Sprint 4: 阶段复盘草稿

目标：

基于学生记录生成第一版复盘报告。

任务：

- 创建 SQLite 表 `review_reports`。
- 选择学生、时间范围、科目。
- 聚合对应学习记录。
- 按标签和记录类型统计。
- 用模板生成 Markdown 报告。
- 支持老师编辑报告。
- 保存报告到学生档案。

验收：

- 能基于真实记录生成复盘草稿。
- 能编辑并保存。
- 能在学生详情页查看历史报告。

## 8. Sprint 5: 本地搜索

目标：

让老师能快速找到学生资料。

任务：

- 实现学生搜索。
- 实现学习记录关键词搜索。
- 支持按标签、科目、时间范围筛选。
- 预留 SQLite FTS。

验收：

- 输入关键词能找到相关学生和记录。
- 1000 条记录下搜索体验可接受。

## 9. 暂缓任务

这些功能重要，但不进入第一阶段：

- OCR 识别试卷
- AI 自动错因分析
- 本地向量检索
- DeepSeek 复盘润色
- 自动生成练习题
- 导出 PDF
- 云同步
- 多账号权限

## 10. 第一阶段完成标准

第一阶段完成时，应该可以现场演示：

1. 新建一个学生。
2. 添加 3 条学习记录。
3. 给其中一条记录上传试卷图片或 PDF。
4. 查看学生时间线。
5. 选择一个时间范围生成复盘报告。
6. 编辑并保存报告。
