# 小智测试交付方案与本轮合同

日期2026-10-04；用户要求先给出方案，再落地测试样例说明书，解决自动测试与手动实际使用不一致的问题。范围M01/M03/M10/M12测试治理；不启用子agent，不提交/push，不覆盖并行图片实现或正在运行的用户构建。

## 1. 真实差距

- 联网脚本以新建隔离profile、`.env.local`密钥与显式测试模型执行；不是用户保存配置与已有会话的完整证明。此前显式AliDNS实例不能证明原system默认可用，详见联网恢复文档。
- OCR脚本默认`test-results/xiaozhi-agent/pi-ocr-build`，不保证等于日常`out`。图片生成、上传预检、原SDK直接视觉与本地文字识别，都不能单独证明正式聊天已能看图。
- 最新149只证明视觉前置；当前工作源码已出现150/public-image实现，说明源码/文档/已运行构建可能属于不同切片。必须按构建SHA和本轮实例判定，不能从旧根文档或源代码字符串推断正式用户完成。
- 一次重跑通过会掩盖首次失败；脚本退出0也可能缺报告、只测mock或仅连接API。
- 用户报告的联网/图片问题仍作为待复现反馈保留，隔离成功不能自动关闭它们。

## 2. 交付物与流程

1. 根`测试样例说明书.md`：教师可照做的样例、客观预期、失败判据、版本/环境核对、记录模板；聚焦AI及教育资料，不恢复三元题组开发。
2. `docs/testing`：固定案例清单、人工记录模板、用户反馈登记。
3. `apps/desktop/scripts/acceptance`：无新依赖的合成素材生成、受控测试入口、严格证据判定、JSON/Markdown报告。复用现有真实Electron/Pi/DeepSeek/web/OCR脚本，不另造mock页面。
4. 开始复制日常out到自有test-results构建，逐文件SHA一致、测试后再次核原out未变；严禁使用正在使用的out做build。构建复制不等于真实profile/配置、VPN状态一致。
5. 本轮执行联网正式UI与OCR正式UI两个纵向实例；其余样例明确未执行，不拿历史报告计入本轮。生成素材在自有test-results，不扫描真实资料，不自动上传学生图。

## 3. 分层判定与完成定义

边界/引擎、隔离正式桌面、日常已保存配置/旧会话、无VPN/安装、用户确认分别记录。通过必须exit0、有效success=true报告、非空且全部通过的检查、正确产物目录、固定构建未漂移；缺证据不成功。失败后重跑的同版本序列只要有一次失败，就不能称稳定通过。

人工验收默认未验证；用户当前反馈未闭环时整体`NOT_ACCEPTED`，自动两项通过只称隔离实例通过。外部阻塞、未实现、未执行和错误报告不能进入通过分母。不得由模型自己的“可以通过”决定结果。首次失败保留；报告不保存密钥/密文/真实学生内容。

本轮完成：说明书与案例素材可用；判定器拒绝退出0但报告失败/缺失、重复运行掩盖失败、mock提升为正式、用户反馈被自动关闭等反例；执行两真实UI实例并生成如实报告，四根与矩阵同步。若实例失败，保留证据及下一诊断，不改业务逻辑来迎合测试。用户具体失败原文/图片已异步请求，答复未到不虚构复现。

后续：先按用户素材复现实际已保存配置/旧会话；再当前150的正式公开图授权/实际Pi视觉链、关闭VPN和Windows安装。此测试交付不等于完整AI已验收。
