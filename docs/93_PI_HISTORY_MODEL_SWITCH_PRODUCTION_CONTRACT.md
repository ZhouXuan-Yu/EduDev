## 修改与顺序

1. main native-model-switch支持可核验的authority分支模型恢复：沿用memory/skill epoch隔离。原生restore intent/receipt引用既有隔离entry、已提交ledger revision/model/native身份；不改ledger选择或复活旧消息。已有native变更后退出只补receipt，不再次setModel；native前退出由经当前authority校验的组装阶段完成。未知版本/分支/额外消息/模型变化拒绝。无新增授权或第三套事实库。
2. pi-session经main回调核双源账本/原生链得到originModel，仅用于旧fingerprint；请求/stream/compact使用当前实际模型。epoch校验后在安全分支恢复已授权模型标记；旧snapshot不改。idle切换加载同一JSONL，注册官方目标，检查完整system/messages/tools/output容量与Hana保留窗，然后原生setModel，dispose；下一次真正prompt重新加载目标全部策略。
3. 生产host抽出本轮共用组装选项，run与idle相同教育/Skills/记忆/工具权限，idle不prompt、不建run、不登记审批或工具效果。现有全局配置锁包住官方查询/原生组装/账本CAS；pending恢复在snapshot/settings/start读取模型前完成；startup无需凭证即可恢复已经落盘的切换。关闭和归档后不晚到提交。
4. model-settings的绑定会话版本来自ledger（尚未seed则空选择revision），只有正式switchBound回调存在才解锁；历史但未绑定兼容对话仍锁定。select验证官方目录与目标后委托host。session-state同时支持schema5并阻止绕过ledger修改binding，旧Windows分隔符可读，新增写入统一分隔符。
5. shared加入context_limit中文错误，沿用现有typed API/现成HeroUI Dropdown/Pro PromptInput。Finesse product/AI workbench语法以用户截图优先，无新手搓菜单/伪推理档位。模型选择成功后hydrate真实projection；失败保留实际模型并允许刷新/重试。新API不接origin/path/native身份。

Pi SDK在已有文件但当前分支无messages时也会自动写初始model_change；不能误判为新会话或放开未知变化。账本增量baseline_entries_json保存初始化前已验证旧身份下的同origin模型entry IDs（≤4096），新库默认空兼容B1；只在旧schema1–4且完整旧fingerprint验证后登记，不接受renderer。ledger存在且epoch隔离成空分支时，在SDK加载前写有隔离anchor的restore intent，使SDK bootstrap标记也有精确durable归属，加载后补receipt；不创建消息来骗hasExistingSession。
