## Phase 1 教师暂停与取消

- 模块 M10。普通教学任务执行中可暂停或取消，暂停后从原任务继续。静止的未完成任务也可取消。取消须二次确认，保留已保存成果和执行记录。原 Composer 的「停止本轮」及 Goal 控制维持原入口。
- 使用任务卡 → typed preload → 主进程任务控制 → 原 Pi 停止、权限撤销和副作用对账 → 原 Task Journal 检查点。执行中使用会话、Task、要求版本和 Run 所有者对齐，静止操作校验任务修订版本。复用 `paused`、`ended` 状态和现有重启兼容格式。取消状态须阻止原任务的恢复和隐式「继续」。
- 验收实际桌面会话中暂停、重启、从原 Task 恢复、确认取消、再次重启以及尝试恢复已取消任务。核对 Run、requirementsVersion、历史效果、审批和模型请求计数。取消成功反馈以提交的 Task 检查点为准。入口和状态可随源码回滚，历史记录沿用原格式。

## Phase 1 冷启动后回答教师澄清

- 模块 M10。执行中的澄清由原 `ask_teacher` 等待，答复继续同一 Run 和 Task。对中断问题显式回答时，宿主核对原题卡所属会话及执行、当前任务和要求版本。仍可恢复时进入同一 Task 的新 Run；任务已取消、已被替换、题卡过期或来源不明时保留历史题卡和答复入口反馈。
- 复用 `xiaozhi_pi_controls`、已有回答 IPC、Task `continueTask` 和原恢复对账。恢复命令沿用题卡派生的稳定 ID；恢复授权由宿主核对，题卡文字、模型及客户端输入不可提供授权。旧审批和结果未知操作保持原有对账规则。
- 执行中用真实 Electron 验证等待状态、同一 Run 续做；重启用隔离的合成会话验证题卡待回答、原 Task/要求版本、恢复答案来源、重复提交和取消后的零请求。历史记录沿可读的现有 schema，无新任务表或调度器。
- 正常退出时仅保留小智发起的教学澄清。利用宿主停止原因区分主动结束与应用退出，并在原题卡记录宿主用途。操作确认与运行权限继续按原流程结算。旧题卡格式可读。桌面验证覆盖两种退出方式、主动停止、重新提交和已取消任务。

## Phase 1 多份资料子任务

- 模块 M10/M04。教师在同一主对话要求对照多份已授权资料时，Pi 用现有正式计划组织有独立标识和来源的只读资料步骤。主对话任务卡显示这些步骤的依赖、进度和核验结果。单次读取维持直接入口。
- `update_task_plan`、现有文件/附件工具和宿主权限继续承担真实操作。资料子任务从已有 `TaskStep` 和来源标准派生，核验结果由原 Task 检查点关联到精确的工具回执。在同轮准备主模型请求时使用当前核验结果。恢复时先从原运行回执重新核对已读资料，结果缺失或版本改变时明确待核对。已验证的结果可以继续用于汇总。
- 验收沿真实桌面选择隔离工作目录、同轮执行两个不同资料的工具、任务卡和 SQLite 检查点读回。模拟资料已读且汇总未完成时关闭进程，要求同一 Task 冷启后重用核验结果，并证实原工具没有自动重发。测试同时覆盖来源改变及简单任务原行为。仅改派生展示和接线，旧 Task 文件格式与 SQLite 保持兼容。
