# 批量资料解析的结构质量流程

## 架构决定

小智保留本地 PDF 渲染、OCR、版面识别、按页缓存、SQLite 结构世代和现有后台任务队列。新导入、后台续做、手动重建统一运行结构规则。扫描卷的选项、公式和图表问题由同一装配流程记录。题号、文件名、学校和局部固定坐标只可出现在验收样本里。

| 阶段 | 小智已有基座与本轮落点 |
| --- | --- |
| 一次解析，保留原件 | 使用 PDFium、RapidOCR、PP-DocLayoutV3 和原生文字补证。页图、原 OCR 字面、行框和版面块供后续核对。 |
| 验证题目和来源 | 装配层按题目、页、栏和原始行判断范围。选择题按明确印刷要求或实际选项序号查缺。堆叠公式用上下行框定位，终止于原题边界。 |
| 分流与选择性回查 | 现有裁片识别用于原生文字、印刷题号和选项。同一题横排选项支持本机回查，保存候选、冲突或未读清。连续原页边线能核实的表格保存网格及单元格读数；公式转写不足时保存局部图证据。 |
| 提交与复核 | 质量疑点随题目入 SQLite，自动入题本前检查。教师可从全卷的类别跳转到原页，校对后保留老师自己的修订。重新解析追加结构世代。 |

## 成熟方案怎样落到现有基座

| 一手来源 | 采用的设计 |
| --- | --- |
| [PaddleOCR PP-StructureV3](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-StructureV3/PP-StructureV3.html) | 版面、公式、表格与阅读顺序各有职责。小智已有通用版面和 OCR，后续公式转换应作为局部能力，仅处理被标记的区域。 |
| [Docling 文档模型](https://docling-project.github.io/docling/concepts/docling_document/) | 结构元素应携带层级、坐标和来源。小智沿用现有页图摘要、页码、OCR 行 ID 和题目归属。 |
| [Google Document AI OCR 质量回执](https://docs.cloud.google.com/document-ai/docs/enterprise-document-ocr#image-quality-analysis) | 缺陷分类型记录和定位。小智从现有检测结果汇总题目边界与分栏、选项、公式、图表与版面、文字识别。该参考只用于设计，本流程在本机执行。 |
| [OmniDocBench](https://github.com/opendatalab/OmniDocBench) | 文本、公式、表格和阅读顺序独立测量。小智回归再测跨题串行、选项标签与内容、答案归属和误放行。 |

## 扩展方式与验收

1. 新缺陷先加入问题类别、可重复触发的样本和正常对照。记录应检测、应保留、可回补和需人工核对的具体结果。
2. 需要第二识别器时，从现有质量信号挑选最小原页区域，先用同一批有标注样本对照 Windows 本机耗时、召回和误放行，再决定是否接入。新增识别器的输出必须携带来源、版本、候选和核验结果。批量任务须设页级上限，一次失败不会阻塞其他资料。公式模型、表格单元格模型和异常分栏替代识别仍需独立实现与测量。
3. 区分来源错误和识别错误。原件本身缺字、缺页、水印覆盖导致读数冲突时，流程应给出原因和定位。验收同时核对漏检和误报、旧世代、已确认题目以及重启后的一致性。
4. 规模验收记录文件数、页数、各类缺陷的分子分母、实际成功回补数、误放行数、总耗时和单页延迟分布。真实公开扫描、不同版式下的控制缺损、长文档和大批量样本分别登记。小样本结果只覆盖所测缺陷。

后续接入回查时先复用已有来源核对边界。`MaterialStructureRuntime.recoverPrinted` 已支持按原页裁片回查题号。`MaterialChoiceRechecks` 已有来源版式复核和写回认证，可复用它对原始读数、裁片和已确认记录的核验原则。后者服务于既有「AI 深度整理」批次，扫描导入继续走本地后台队列。 [既有来源核对](../integrations/CURRENT.md#2026-11-17-带图来源版式归档)

`planChoiceRecheck` 只为有独立坐标的同排选项规划区域。`MaterialStructureRuntime.recheckChoiceRow` 复用本机 OCR，每页最多一行，每行最多两遍、16 秒的 OCR 预算。每次读数须重现原有选项及其内容，增加的读数依原裁片绑定。系统记录未读清、单次候选、一致候选或冲突。结果与首轮识别并列，沿原世代可复读；重启后继续尚未结算的工作。仅有字母的普通文本选项仍需核对，图形选项沿原图的归属判断。

`readStructureTables` 在表格版面框内核对横竖边线，进一步查每一段交界和仅存在于单行或单列的部分边线。连续的矩形网格才分配现有 OCR 行。每页最多检查 8 个候选区，每个有效网格最多 96 个单元格，文本位置和置信不足的格子保留待核。合并格、无框表、错误版面标签及无法可靠定位的线条继续保留原图。弹开表格核对区才渲染数据和按需读取原图，其他题目无需下载页图。

公式专项的首轮候选为可独立输入局部图的 PP-FormulaNet，以及 Docling 的可选公式增强阶段。比较使用同一份被冻结的公式局部图和人工真值，含分式、根式、上下标、多行公式、水印和非公式对照。以符号正确和位置对应为准，记录拒绝、未识别和误放行。Windows 本机时延、组件体积、安装与换机成本通过实测后再决定是否接入。 [PaddleOCR 公式模块](https://www.paddleocr.ai/main/en/version3.x/module_usage/formula_recognition.html) · [Docling 增强阶段](https://docling-project.github.io/docling/usage/enrichments/)

## 明确网格的视觉回查

已实现一条由教师主动触发的候选链路。沿用结构世代、题号引用、源页光栅摘要和本地单元格坐标。教师先选中待核单元格并查看拟发送的局部。主进程用同一原页裁切高清目标及附近行列。远处表头或行名必要时单独取其局部。发起前经窗口确认和本地隐私检查。每次只转录一个格，返回文字、列名、单位和可读状态。回执独立保存，原 OCR 和教师确认流程继续作为正式依据。

有色叠印能得到很高的 OCR 分数。结构 v23 同时看原页行框的浅色笔画占比与深色中性笔画。呈现疑似叠印时保留原始行 ID，单元格读数转入待核。该规则会把部分浅色印刷内容送去核对，无色遮挡继续依赖既有可读性证据。视觉回查对命中的格提供独立的去浅色细节图，原格和上下文一并保留。提示逐字符核对正负号、小数点、零和单位。独立本地读数与模型在正负号上冲突时保留待核，不输出数值候选。

批量导入保持本地完成。回查失败、取消、资料版本更新均可继续原来的核对流程。下次启动可读回已保存的候选。合并格、无框表、跨页、小问匹配和独立答案册未接入这条新入口。

### 提示词对照

固定同一批八个合成案例、同一模型、同一高清裁片及上下文，以及相同的 JSON 示例。通用提示和转录专用提示均完整匹配 7/8，字段匹配均为 18/19，完全遮挡与作答笔迹均正确留空。专用提示正确分离表头和单位，另一个案例把小问号 `1` 返回为 `(1)`。这个差异应由该字段的规范化规则处理，实际字符读数不做类似改写。清晰的返回示例有助于遵守 JSON 合同。是否读对并属于同一题，继续由图像质量、实际来源和回执校验决定。对照只用于合成验证，原有表格入口保留其专用提示。
