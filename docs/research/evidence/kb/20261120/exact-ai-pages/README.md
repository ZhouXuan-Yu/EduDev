# 多页 PDF 的精确分块引用

## 根因

《风华初三三模模拟测试卷》第 1 页的原正文和追加的结构分块分处资料正文偏移 0、1、10～21。旧的建批代码找到了 14 个同页分块，却从偏移 0 开始读取连续 14 条，误取第 2 页并报 `source_incomplete`。第 2 页有 21 个分块，旧建批路径在达到归档协议支持的 64 个引用前就报 `unit_too_large`。

## 修改

- `material-ai-page-source.ts` 在一个 SQLite 快照中选定当前资料版本、准确页码及当前可见分块。每个分块保留其在全资料正文中的物理偏移。单页超过现有归档协议的 64 个引用时显式报错。
- `material-ai-repository.ts` 的 PDF 图文和纯文本建批都使用同页引用。图文模式以原页 OCR 回执为输入正文，纯文本模式保留本页分块与 OCR 对照。来源摘要与重读校验继续执行，按页隐私检查仍涵盖同页历史分块及未知页记录。
- 本轮不修改 SQLite 表结构、原件、已保存分块和历史子批次。撤销提交可以回退。

## 真实桌面前后对比

从备份副本中用真实资料导入和后台授权界面启动《风华》整理。两个构建复用同一份 PDF 和已留存的本地 OCR、段落与图片结果。

| 检查 | 旧版 | 本轮 |
| --- | --- | --- |
| 第 1 页 | `source_incomplete`，0 个子批次 | 1 个子批次，14 个准确同页引用 |
| 第 2 页 | `unit_too_large`，0 个子批次 | 1 个子批次，21 个准确同页引用 |
| 来源位置与冷读 | 没有可以回读的建批引用 | 35 个引用经应用的来源接口逐个核对 ID、偏移对应原页，重启后仍一致 |
| 外部模型调用 | 0 | 0 |

重定位后两页均到达生产派发接口，本机拦截器返回受控 HTTP 401。批次保留待核，未获取模型定稿。重启后未重发，原始结构页仍逐字段一致。SQLite 单页取源代码在真实样本副本上各运行 300 次，P95 分别为 1.80 ms 与 1.68 ms。该数据仅覆盖本地分块查询和映射。

## 下一断点

《风华》旧验收副本的两页误判没有子批次。本轮保留既有回执，后续续跑须核对原版本与授权范围。另对现有约 1 GB 试导库做只读盘点。该库的两条 `source_incomplete` 均已关联子批次，未发现本轮对应的无子批次旧记录。待核页中 `ai_omitted_questions` 有 142 条、`page_content_incomplete` 有 96 条。漏题记录中有 10 条使用 `page-fragments.v3` 并保存终稿，另有 132 条没有冻结页面提示协议。优先复读已有结构版式、原图和终稿的 10 页，定位下一段自然题定稿断点。配答准确率、正式三套整卷、独立检索指标、约 10 GB 混合目录与换机验收继续按主线推进。
