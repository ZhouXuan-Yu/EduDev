# 待核结构教师修正入题本

## 结果与根因

已关闭资料结构页只能查看待核候选、无法保存教师修正的问题。MaterialStructurePanel 原来只展示候选，MaterialQuestionArchive 按需跳过 needs_review，且来源认证只接受自动 candidate。教师修正后缺少可靠的来源身份与写入入口。

本轮新增显式教师修正动作。原 OCR、段落、候选状态和页图保留，教师修改以独立回执绑定到同一原题及资源版本。保存后进入原题本，原编辑、原图和版本检查继续使用。完整知识库 Goal 仍为 ACTIVE。

## 修改与数据契约

- 共享契约新增 StructureReviewInput 与 xiaozhi.structure-review.v1，复用 ArchiveFields 校验。结构归档增加可选 structureReview，旧结构/AI/配套答案归档保持原认证路径。
- material_structure_reviews 采用增量、幂等建表。回执保存原候选引用、原题文档、教师初始字段、题目 ID、时间及摘要，资源/版本/候选唯一。
- MaterialQuestionArchive 使用原 writer，将题目、回执和来源成员同事务保存。相同请求重复或并发只返回一个题目，不覆盖后续教师编辑。不同修正遇到已保存题目后转原题本继续编辑。
- 结构仓库先认证原件、候选和页面摘要，来源文档复用原裁图实现。原件变化、重建中的旧页面、答案册误用和缺失题图等情况拒绝发布。
- typed preload/IPC 新增 reviewMaterialStructure / materials:structure-review，只允许当前主窗口发起并严格校验字段。
- QuestionArchiveFields 复用原题本字段。资料页增加原件核对、保存、取消、失败重试和已保存反馈，未保存输入进入原导航保护。最终复用现有教学编辑器样式模块。

完整修改文件与摘要见 MANIFEST.json。未新增生产依赖、云请求、OCR 引擎或独立服务。

## 使用路径与前后对比

资料库选择资料，进入“题目与校正”，展开“段落与试题结构”，打开原页，在待核题中选择“核对并保存到题本”。补齐完整题面、选项、小问和分类，核对原件后保存。题本继续提供编辑、原图和组卷候选状态。

| 项目 | 修复前 | 本轮结果 |
| --- | --- | --- |
| 待核结构 | 查看后无法入题本 | 显式教师修正后进入原题本 |
| 原始证据 | 原快照保留 | 原快照继续保留，另增教师回执 |
| 重复提交 | 缺少人工入口 | 相同请求返回同一题，不覆盖已有教师修改 |
| 保存失败 | 缺少人工入口 | 事务回滚，界面保留全部输入 |
| 表单可用性 | 新入口首版缺少布局样式 | 最终标签纵排、字段全宽且有边框，双尺寸验证 |

受控双栏样本的原 OCR 漏识 C 选项，原始候选仍为 A/B/D 并保留疑点。测试在原界面对照原页，由教师动作补入 C 及分类、答案、解析，原 OCR 和候选未改写。现有 24 条题库记录保持，新增 1 条教师修正题。

## 失败与未解决项

- 功能首轮通过后，截图暴露字段布局缺失，保留原截图和报告。复用样式时一处相对 import 路径错误导致构建失败，错误日志与未完整构建的读回失败均保留。修正 import 后完整构建、组件和最终界面通过。
- 边界脚本首次缺少 Node 来源模块 loader，产生 ERR_MODULE_NOT_FOUND。后续精确命令固定使用 --import。原输出文件被重试覆盖，工具回执中的失败保留于本轮记录，不把该次调用计为通过。
- 缺失题图、题目起点或超出既有来源文档边界仍保留待核，需进一步切题整理。教师核对不会自动补造文字或图片。
- 独立 AI 结构认证、OCR 漏项自动恢复、复杂公式/表格、自动题答联动、全范围检索组卷、安装迁移和约 10GB 自然资料验收继续 OPEN。
- 本轮自动化模拟教师操作，未取得外部教师的人工产品验收。
- 最终 npm 审计 35 项，high 15、critical 0。生产依赖锁未修改，既有 Python 审计工具缺失状态没有在本轮解决。

本轮动作与来源读回验收 PASS。完整知识库 Goal 保持 ACTIVE。
