## 3. 必须优先修复的问题

### R01 · P1 · 数学内容不能正常阅读

**复现：** 上述真实备课回复中的行内和独立公式全部保留定界符，教师看到美元符号与 LaTeX 命令。基础分数和多行解题步骤也受影响。

**代码：** `apps/desktop/src/renderer/heroui-pro/components/markdown/markdown.tsx:19` 仅配置 GFM、换行插件；`:265` 的 Streamdown 调用未接入数学插件。`OfficeMarkdown.tsx:16` 只适配 pre/code。

**教师影响：** 最核心的数学教学内容无法直接阅读、投影或可靠复用。现有数学相关依赖存在不证明对话渲染已接通。

**修复与验收：** 在现有 Markdown 边界接通数学渲染，覆盖行内/块级/分式/多行/表格内公式、流式未闭合与错误公式；真实 Electron 浅暗两尺寸验证。原始文本保留，不能以字符串替换破坏公式。

### R02 · P1 · 切换会话静默丢失未发送草稿

**复现：** “未发送草稿：请把练习B改成基础题，保留答案。”输入后切到新对话，再回原会话，输入框为空，没有提示。

**代码：** `PiEducationWorkspace.tsx:179` 将 `OfficeComposerState` 按会话 ID 重新挂载；`OfficeComposerState.tsx:9` 草稿只在组件 useState 中，没有按会话缓存或恢复。

**教师影响：** 教师跨学生、跨课题切换时丢失精心整理的要求；这会直接破坏对软件可靠性的信任。

**修复与验收：** 本地按会话保存草稿与技能选择，切换、刷新和重启均恢复；成功发送才清除对应草稿。不得把未发送草稿自动提交给模型。

### R03 · P1 · 等待过程不能解释系统正在做什么

**复现：** 首个公开文本前约 17 秒只见“正在处理你的请求”；工具结束后生成下一段时仍回到同一句。教师无法判断卡住、等待首字、检索还是整理结果。

**代码：** `PiWorkspaceActivity.tsx:17` 在没有活动工具时统一回退到该句；`xiaozhi-agent.ts:36` 的公开事件缺少专门的可解释等待/阶段信息。源码 `pi-session.ts:537` 的初始 thinkingLevel 为 off，`:742` 仅转发 text_delta；不能把当前等待称为已证明的“深度思考”。

**修复与验收：** 依据真实宿主/工具事件显示“正在准备请求 / 等待模型回复 / 检索资料 / 整理教学安排 / 等待教师确认”，给出实际耗时和超时恢复入口。只展示公开工作摘要，不请求或展示隐藏思维链，不造进度百分比。

### R04 · P1 · 普通备课默认检索链过重，空库仍多轮查找

**复现：** 用户没有要求依据已有资料，空环境仍调用 5 个工具后才交付通用教学安排；首轮完整终态约 72.6 秒。

**代码：** `pi-session.ts:330` 起将资料、题库、附件等能力和多段引导一并装入会话。当前公开轨迹没有空来源可用性摘要或任务级检索成本边界。

**边界：** 这是单次实际行为与产品控制缺口，不断言每次请求都会固定调用 5 次，也不直接把全部耗时归咎于提示词。

**修复与验收：** 宿主提供真实“有无资料/附件/授权目录”能力摘要；通用备课允许先形成明确标为通用建议的可用稿；用户要求依据资料时再执行必要检索。空库快速分支、资料充分分支分别测首字/可用稿/完成时间及调用次数。

### R05 · P1 · 工具成功数不能帮助教师判断教学结果

**复现：** “5/5 已完成”中包括空检索。展开每个工具主要重复工具名、完成状态和用时，看不到搜了什么、找到多少、哪些材料实际支撑答案。

**代码：** `education-tools.ts:29` 已产生 count；`pi-session.ts:749` 的公开 tool_end 只挑选有限来源/错误等字段，没有传 count/安全结果摘要。`OfficeToolProcess.tsx:50` 因而只能重复状态；`:73` 汇总的是工具成功数。

**教师影响：** 完成调用和完成备课容易混为一谈；空结果与有效证据在视觉上几乎一样。

**修复与验收：** 公共结果最少包含脱敏查询摘要、结果数、实际引用、空结果与下一步；“操作完成”与“教师要求满足/未满足”分开展示。保留工具详情折叠，但摘要必须有实质信息。

### R06 · P1 · 回复没有形成教师可用的交付入口

**复现：** 约 1900 字备课文本生成后，本轮对话区可见按钮只有过程折叠；没有正文复制、存为教学内容、按选中部分修改、保存教案的入口。继续操作依赖教师再次写提示词。模型提出的“需要你确认的3点”也只是段落。

**代码：** `OfficeConversation.tsx:71` 的助手消息只挂正文和截断提示，没有 ChatMessage.Actions；`markdown.tsx:246` 默认 controls=false。现有 Office 文档/教学内容能力并未自动成为普通文字回复的操作栏。

**修复与验收：** 回复至少支持复制正文、继续修改、在教师确认后保存/导出到既有领域能力；关联原会话和实际产物。需要决定时使用现有问答控件，允许“采用这些假设继续”，不要重复让教师填写已经给出的年级/时长。

## 4. 交互与设计问题

### R07 · P2 · 停止后缺少安全继续路径

实际停止和重启读回正常，但 `OfficeConversation.tsx:38` 只给 failed 状态入口，interrupted 只有提示；`PiConversationSurface.tsx:16` 也仅处理 failed。教师必须自己组织“从哪里继续”的提示。应提供“继续未完成内容 / 调整要求后继续”，作为教师触发的新运行，并明确已完成效果；不得自动重放写文件或旧审批。

### R08 · P2 · 过程说明、最终答复和部分回复缺少视觉层级

`OfficeConversation.tsx:71` 仅写 data-phase；`office-conversation.css:37` 过程文字与正文同色、同字号；`xiaozhi-projection.ts:127` 在 failed/interrupted 终态也把最后一段设为 final_answer。本轮“我先核对……”和最终教案以同类正文出现。应压缩公开过程、突出可用稿，将中断内容明确标为部分结果。修复语义时保留实际 turn.status，不篡改业务成功状态。

### R09 · P2 · 次要面板长期占据教师阅读空间

两侧面板默认开启，`workspace-preferences.ts:10`；左侧约 254px、右侧约 306px，`pi-education-workspace.css:48,81`。右侧经常只有“教师工作区 / 本地 / 来源 / 任务详情”。在 1366×768 下对话视区约 753×505；打开文件面板后更拥挤。**本轮没有发现控件不可达或水平溢出**，问题是空间分配。建议普通对话将次要资料面板按需打开，有审批/文件/真实来源时再突出对应内容；保留用户选择。

### R10 · P2 · 首屏没有告诉普通教师能从什么任务开始

`OfficeConversation.tsx:49` 空态只有“有什么可以帮你？”，输入框是“随心输入”。顶部和输入区同时出现技能入口，底部还有“持续目标”，均优先展示系统能力。建议以“备一节课 / 根据资料组卷 / 处理错题 / 修改讲义”等少量教师任务示例起步，允许直接输入与附文件；不把任务入口变成必填表单。

### R11 · P2 · 输入区运行时堆叠额外模式，含义和提交行为不够清楚

`OfficeComposer.tsx:85` 运行即增加“补充本轮 / 接着处理 / 发送补充”，并保留持续目标、权限、技能、模型、不可用语音与停止。教师需要理解补充的应用时机；输入框占用高度也改变。`OfficeComposer.tsx:61,86` 在请求确认前清空草稿，失败后原文留在隐藏 failedPrompt，只能重试发送或关闭，没有直接恢复编辑。应默认让教师继续输入，用明确的应用时机与确认反馈承载模式；失败可恢复原文编辑；未接入的语音不长期占位。

### R12 · P2 · “来源”没有区分文件操作对象与回答依据

本轮空库最终回复自行说明是通用生成内容，右侧仍显示“授权工作目录”。`PiWorkspaceContext.tsx:24` 直接聚合当前最后一轮所有 item.sources，目录枚举对象也进入来源清单；新回合又清空旧轮来源，阅读旧答复时没有对应变化。应区分“本轮查看了哪些对象”与“这段答案引用哪些证据”，按回复/选中回合展示；无依据时明确“通用生成，未引用本地教材”，不能用目录名撑起来源卡。
