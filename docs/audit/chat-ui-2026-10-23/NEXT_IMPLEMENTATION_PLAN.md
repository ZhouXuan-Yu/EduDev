## 2. 首批交付范围：聊天 → 任务 → 审阅 → 成果

目标页面仅覆盖 `PiEducationWorkspace`、对话、输入、右侧资料/成果和对应现有审核组件。第一批不迁移教学导航、不改学生路由、不新造讲义编辑器、不新增模型能力。

```text
空白会话：四个教师任务入口 + 真实最近记录 → 输入可编辑要求
普通问答：正文 / 公式 / 回复来源 / 复制修改保存
有实际任务：一条任务摘要 + 待你处理 + 可展开过程
                            ↓
               资料 / 任务 / 成果工作台
                            ↓
        打开原领域审阅 → 教师编辑、确认或拒绝 → 真实交付回执
```

“最近记录”只读现有会话/持续目标和实际时间，不伪造项目、收藏、完成比例或任务标签。普通会话无 Goal 时就称“最近对话”。创建持续任务仍需教师核对目标和验收条件；自然语言可以先填草稿，不自动持久化目标。

## 3. 页面与交互合同

### 参考图落实边界

![输入区交互参考](reference-composer.png)

采用图中的控件层级与中性阅读面。placeholder 使用“给小智一个教学任务，或直接提出问题…”。底部“+”打开现有附件/授权入口；“本地资料”标签必须展开真实范围摘要，不能暗示全部文件已授权、已读取或永不上云。附件已选/解析中/失败、缺少模型配置、存储失败、队列冲突等状态按需显示。IME组合输入和停止行为保持。当前仍缺语音实现时不摆可点的语音假入口。

![成果卡交互参考](reference-artifact.png)

采用“真实标题 + 右上状态 + 有证据的教学参数 + 一句进展 + 预览与修改/查看来源”的结构。示例“100分/数学/中等难度”仅在宿主草稿有对应值时出现；无成果不展示占位假卷。待审核不能显示为已完成；来源缺失时说明原因而非造可点链接。聊天卡不展开几十题与整份编辑表单。窄屏按钮可换行；打开工作台和返回后，消息阅读位置、选中版本与未保存编辑保留。

视觉起点采用原方案的中性背景 `#F7F8FA`、阅读面 `#FFFFFF`、正文 `#1F2937`、次字 `#667085`、细边框 `#E6E8EC`、主要动作 `#2565CE`。通过语义 token 映射 HeroUI 深浅主题，深色值单独验收，不直接全局替换。减少大面渐变/玻璃/多重阴影；常规操作36–40px、重要点击目标至少40px、正文15–16px、阅读宽度760–860px作为待校准起点。

### 主区

- 顶部只保留会话名称、必要的学生/资料范围提示、更多、打开工作台；主导航继续五入口。
- 空白态保留已有四个场景入口，新增真实最近记录和“添加资料后开始”的短提示；点击填草稿或打开现有资料选择器。
- 普通回复使用现有公式/来源/操作栏；过程默认一行，失败和待办优先；不为每句话展示任务进度。
- 教学任务仅一处固定轻量摘要；Goal 与 Plan 不再在输入区和消息区重复占首屏。展开后保留步骤和原始公开回执。
- 输入区默认正文、添加、发送/停止；当前模型保持轻量可见且可辨认。技能、目录授权、追加时机收进有名称的菜单；运行中显示当前追加时机，不能静默猜测 steer/followUp。

### 右侧工作台

- 三个页签：“任务”“资料”“成果”；默认不占阅读区。无资料/成果也要有真实空状态。
- 宽屏可并列；1366 下按实际余量覆盖展开；预览大文档/试卷时进入宽幅审阅，保留返回对话、任务名称与当前待办。
- 打开文件不应替换掉全部任务上下文。展示文档时保留待审核提示，但不自动切走教师当前正在编辑的页签。
- “上下文用量、压缩、预算、记忆、诊断”进入“高级详情”。资料范围继续可见；改范围沿原设置/权限路径。
- 待办卡显示对象、影响、版本、确认/拒绝后果。重要确认不埋入多个折叠层；不通过颜色单独传达状态。

### 成果审阅

先统一壳与入口，内部复用 `PiOfficeArtifactCard` / `PiPaperReview` / `PaperReviewPanel` 等现有领域审核逻辑。首片以 Office 成果为纵向样本，试卷接入在相同合同验证通过后进行。

聊天里保留成果摘要、当前状态、“打开审阅/打开文件”。编辑、来源、图片检查和正式确认在宽幅工作台。移动组件不能重置未保存编辑、重复读取/审批或放宽 source CAS。标题确认、试卷内容确认、原图检查、写文件确认仍是各自事实。

Markdown 回复保存与 Office 草稿具有不同合同，统一列表可展示两者，但不能把 Markdown 已落盘显示为 Word/PDF 已交付。

## 4. 状态投影：先复用事实，再统一语言

新增纯展示适配器（建议 `teacher-task-view.ts`），从现有 snapshot 计算展示模型；不创造可授权的“新任务状态”。字段至少为会话/运行标识、标题、展示状态、下一操作、待办、来源、成果及其原始 ID/版本。UI 缓存的选择页签不成为审批依据。

| 原始事实 | 教师可见语言 | 不得暗示 |
|---|---|---|
| hydration 未完成 / 状态冲突 | 正在恢复，暂不可提交 | 旧审批仍可用 |
| active run + 准备/等待/文字流 | 正在准备 / 等待回复 / 正在生成 | 隐藏思考或虚构进度 |
| 当前有效 ask_teacher | 等待你补充 | 普通文字提问已收到回答 |
| 当前版本 pending approval/review | 待你审核，并定位具体对象 | 教师确认等于答案独立核验 |
| interrupted / failed | 已停止 / 未完成，已保留部分结果 | 点击重试就可重放所有副作用 |
| run settled，尚无正式成果 | 本轮回复已结束 | 教学任务全部完成 |
| artifact saved/exported + 有效回执 | 已保存，显示真实文件类型和位置 | 其它格式已生成、内容正确 |
| 有持续目标但验收未通过 | 待验收 / 仍有未完成要求 | Plan 全勾选就等于 Goal 完成 |
| 教师接受当前版本 Goal | 目标已由你验收 | 模型自报即通过 |

恢复未完成时优先阻止旧动作；待办按真实有效记录逐项展示，不用一个总状态覆盖多个待办。来源按回复/run/产物绑定，目录枚举不算正文证据。工具图标逐步改用注册类型元数据；未知类型使用中性图标，不靠中文标签猜测权限或成功。

## 6. 技术与兼容策略

- `PiEducationWorkspace.tsx` 当前同时承担事件订阅、会话装载、多领域审批拼接和输入编排。按本片需要抽取事件状态 hook、任务展示选择器和 review registry；不一次改写全部 workspace，更不向 `App.tsx` 新堆业务。
- 当前事件处理已经在 renderer 应用增量事件，**不能笼统称每个 token 都重新 IPC 全量读取**；但它复制 turns、查找 run，并在视图遍历 turns 和多类 review。启动/终态 hydrate、历史装载和 DOM 规模需要测量，确定热点后再选分页、稳定选择器、批量文字更新或虚拟化。
- 首批不引入通用富文本框架、不新增任务表、不迁移题库/学生结构。后续确需新依赖、IPC 分页或业务契约，先补用途、许可证、Windows包影响、兼容和回滚合同。
- 旧入口在新纵向链验收前保留。旧导航 key 可作为适配路由，不根据显示名称重写来源记录；本机偏好可带版本升级并可回退，丢偏好不得丢业务数据。
- 教师授权、图像审阅、来源哈希、业务版本、审批幂等仍由 main 验证；展示层合并不能把多个领域批准打包为宽泛授权。
- UI 选择、预览和普通菜单调整不弹额外确认；涉及真实业务效果的动作沿用原确认，不给教师增加重复流程。

## 7. 每片验收与指标

四条教师主旅程分别验证：①普通问答/短备课，②授权资料和题库组卷→内容审核→学生/教师版交付，③学生错题→OCR校正→相似/变式题→练习，④同一学生必要记录→时段复盘→缺失证据提示→教师确认。另设贯穿链：资料导入/读取→备课或讲义→来源定位→成果保存，覆盖前两份方案强调的知识库入口。**本轮聊天专项通过不等于这些领域流程已在新UI中通过。**

每条记录入口、点击/必填次数、首次有用内容、终态、待办原因、拒绝/停止效果、产物来源；总耗时、首字、工具调用和本机交互耗时分开。降低点击以实测对比为准，不预设夸张百分比。

- 最低检查：build/typecheck、现有217组件用例、对应领域专项；关键路径变化跑现有smoke及正式Electron。旧数字是当前基线，新增用例计入新的报告。
- 视觉：1366×768、1920×1080 × 浅/深；125%/150%系统缩放单独测，不能仅缩小viewport冒充系统缩放。中文长标题、公式、错误、空态、等待/确认均可达。
- 输入/可访问：键盘Tab/Enter/Esc、可见焦点、明确名称、选中文本、中文输入法组合时Enter不误发送、屏幕阅读状态提示；色彩对比实际测量。
- 恢复：关闭时草稿、未保存编辑、pending审批、已写/不确定文件；重启读取原始ID和版本。拒绝零业务写入；重试先识别已生效效果。
- 性能：同一构建、同一Temp数据与窗口，100/1000条历史、多步骤和大量附件；记录会话打开/切换p50/p95、输入延迟、长帧、DOM数、IPC量、主/renderer内存。至少30次可重复本机操作，排除网络等待；具体改进门槛在UX-00实测后冻结，不事先宣称提升幅度。
- 教师试用：最后招募至少5位目标教师，观察首次理解、错误/求助、四任务完成情况。自动化不替代真实教师认可；邀请与外部沟通由用户安排。
