# EduDev「小智」全功能 UI/UX 审计与精简重构方案 V1.0

**审计日期**：2026-10-23<br>
**代码基线**：`ZhouXuan-Yu/EduDev`，`master`，`d3e2decd01fd9898026b0a8c1bfc9b029d1d9b63`<br>
**目标用户**：独立教辅教师、中小教辅团队（教师日常工作优先）<br>
**审计依据**：GitHub 仓库公开的 React/Electron 组件、路由、CSS、业务流程与既有 Harness 审计文档。**未直接运行 Electron 应用、未取得当前界面截图、未做用户访谈或计时可用性测试**。下文已证实的是源码可观察机制；体验痛点是静态 UX 风险，需要实机核验。

## 1. 执行摘要

**结论：进行「交互架构重构 + 视觉系统统一 + 流程整合」，不重写 Pi Agent Runtime，不直接砍业务能力。**

当前问题不是缺少功能，而是将技术能力过早暴露给教师：同一会话有 Goal/Plan/Tool/审批/成果多层视图；输入框同时承担模型/技能/权限/附件/任务排队；教学业务大量二级页与表单；旧式 `work-panel`、原生 input/select、HeroUI Pro、局部玻璃拟态与多套 CSS 并存。用户需要理解软件内部结构，而不是围绕“完成一个教学工作”操作。

核心原则：**自然语言先行，业务上下文可见，复杂控制按需展开，统一审核工作台，所有重要副作用继续保留原有教师确认、来源/版本/脱敏门禁**。

## 3. 新信息架构（不砍原能力）

### 3.1 顶级导航：五入口不增加

1. **问小智**：一个入口解决问答和自动任务。最近对话与任务、来源、审核都从这里进。
2. **我的资料**：按「教材/课件/题库/其他资料」组织，题本从「教学内容」移入这里；导入和解析队列归这一域。
3. **教学内容**：按「备课与讲义/智能组卷/教学成果」组织。后台仍使用原 Notebook/Book/Paper/Artifact 存储能力。
4. **学生**：学生列表 → 学生详情，详情内有「概况/错题与练习/学习计划/学习记录/复盘」。全局搜索从顶栏调用。
5. **设置**：普通用户只见「模型与连接/数据与隐私/偏好」，高级入口中有 Skills、Memory、预算和诊断。

**不新增团队模块假入口**。中小团队的组织切换、共享模板、审批流应等多用户授权与数据隔离真正具备后再进入导航。首期以单老师体验可靠、易用为先。

### 3.2 聊天页三种状态

- **空白态**：中心一句话提问 + 四个真实教学快捷入口。隐藏任务时间线和右侧大面板；显示最近任务可一键继续。
- **普通问答态**：专注消息阅读、公式/引用和附件。工具轨迹默认摘要；不要求 Goal 或模板表单。
- **教学任务态**：增加固定轻量任务条、可展开步骤、待教师确认卡、统一成果工作台；右侧只在有资料/成果/审阅需要时打开。

## 4. 重设计的关键业务旅程

### 4.1 智能组卷

**旧界面风险路径**：导航到组卷 → 编辑蓝图/配额 → 选题组上下文 → 生成 → 进入审核弹窗 → 保存试卷 → 另进入导出 → 选择文件种类 → 审核 Word/PDF。

**目标旅程**：

1. 首页点「智能组卷」，或直接说「给七年级出一套期中卷」。
2. 最少参数：年级、学科、总分、难度；从会话已授权教材/题库自动推荐范围。复杂题型比例放「高级配置」。
3. Pi 执行真实检索、选题，侧边显示进度与不足的题型；草稿以「试卷成果」卡出现。
4. 「审核试卷」打开全屏/宽幅工作台：试卷目录、题目、答案出处、来源告警集中展现；教师编辑/确认内容。
5. 确认试卷后，用户再选择学生卷/教师版及 Word/PDF；涉及具体文件写入和原图审核继续保留独立安全确认，不把多种授权静默合并成单个危险按钮。

**目标不是一键绕开教师检查**；是消除业务无关步骤、减少上下文跳转。

### 4.2 错题生成相似练习

**目标旅程**：学生详情点「上传错题」或聊天中「用这道错题出相似题」→ 图片/OCR/隐私处理自动准备 → 教师仅校正不确定字段及答案 → 小智检索本地相似题，标注「原题/相似题/变式题」与真实来源 → 审核保存练习 → 返回学生详情。

不允许跳过教师核对实际作答、答案和来源，不允许自动从未知数据产生确定的学生诊断。

### 4.3 备课与讲义

**目标旅程**：以课程/章节或自然语言创建 → 选择教材范围 → 自动形成大纲 → 在可编辑文档画布中补充内容 → 点击来源可回到教材页 → 最终编辑与交付。书/章/页/块保留在存储模型和专业视图，不应成为普通教师必须逐个建立的字段。

### 4.4 学情复盘

**目标旅程**：进入学生详情 → 点击「生成本阶段复盘」→ 选择时段，自动使用授权的记录 → 呈现报告草稿+可信引用+缺失证据 → 编辑/确认 → 生成供家长使用的简明版本。不要将复盘、检索、输入记录拆成三个独立上下文任务。

## 6. 统一任务与审核模型

### 6.1 用户可见四类信息

- **回答**：直接结果、必要引用、可复制的内容。
- **任务进度**：已完成/正在做/等待你/部分完成/失败等真实状态；默认仅展示总结。
- **待你处理**：明确说明为什么必须人工决定、影响什么数据、拒绝后会发生什么。
- **教学成果**：试卷、讲义、备课文档、复盘报告、练习计划等，可预览、审核、继续编辑和打开。

后端仍保留原生 Pi 事件、Goal、Plan、审批/效果状态机，前端通过统一投影适配器展示。**不要把模型输出结束等同任务业务完成，不要把教师内容确认等同答案数学正确性核验。** 已有审计 `docs/audit/harness-2026-10-12/B_FINDINGS.md` 曾指出这两者混淆的风险。

### 6.2 不可牺牲的安全与可靠性

- 学生敏感信息与原图继续本地优先、最小授权、受控脱敏。
- 文件写入/复制、改写学生事实、公开分享、影响业务状态的动作继续逐项确认与版本校验。
- 本地数据的 source CAS、哈希、审批、幂等与冷重启读回不能因为界面合并而消失。
- 失败重试要核验已发生的副作用，不得盲目重做文件写入。
- `run settled`、`teacher approved`、`artifact saved`、`criterion verified` 分别是不同事实。

## 8. 衡量成功的建议指标（目标，不是当前实测）

- 新用户从首页发出第一条有效任务：无需设置之外的多步配置，常用入口首屏可见。
- 完成“基础组卷”前置配置：除教学条件/素材选择外，不要求理解 Blueprints、Skills、Goal、Token、CAS。
- 高风险确认：所有持久化变更均有清楚的对象、内容预览和同意/拒绝路径；安全门禁未减少。
- 普通问答：没有无意义的“任务计划”或工程日志占据正文。
- 界面：1366×768、1920×1080、125%/150% 缩放，输入区、待处理按钮不被遮挡；浅/深模式风格一致。
- 长会话：对比改造前实测滚动 FPS、切会话响应 p95、IPC 更新量与内存；不事先虚构性能改善幅度。
- 教师可用性：至少 5 名目标老师完成四条任务，记录首次理解、时间、误操作和求助情况；与 UX-00 基线对比。
