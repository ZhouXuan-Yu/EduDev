# Omni-Edu Agent 完整项目开发蓝图

版本：v0.1  
状态：当前主开发方案  
依据：`docs/11_STRATEGIC_PRODUCT_PRD.md` 至 `docs/17_FRONTEND_HEROUI_PRO_DESIGN_ARCHITECTURE.md`

## 1. 方向变更

从本文件开始，项目不再按 MVP 清单推进，而是按完整产品路线建设：

```text
个人老师桌面版
-> 小团队协作版
-> AI 错题资产版
-> 机构经营增强版
```

当前开发目标不是只跑通演示闭环，而是建立可持续演进到团队、AI、同步、审计、备份和经营看板的产品底座。

## 2. 产品主线

### 产品线 A：个人老师桌面版

- 学生长期档案。
- 学习记录时间线。
- 本地附件资料库。
- 阶段复盘和家长沟通摘要。
- 本地搜索、备份、导出。

### 产品线 B：小团队协作版

- 老师账号和角色。
- 学生分配和交接。
- 统一标签库。
- 统一报告模板。
- 复盘审核和团队质量检查。

### 产品线 C：AI 错题资产版

- 错题图片导入。
- OCR 任务。
- 教师校正。
- 知识点与错因标签。
- 相似题召回。
- 三元题组输出。

### 产品线 D：机构经营增强版

- 在读学生数。
- 学习记录数。
- 复盘报告数。
- 待续费风险。
- 老师跟进完成率。
- 高频薄弱点分布。

## 3. 当前阶段开发重点

当前阶段先做“完整产品基础座舱”，而不是继续扩展单点 MVP：

- 完整工作台信息架构。
- 本地完整数据底座。
- 标签字典。
- 报告模板。
- 同步操作日志。
- AI 任务队列表。
- 团队/角色预留表。
- 经营指标概览。
- 数据导出和备份入口。

## 6. 验收方式

每个开发切片都必须：

1. 修改范围清晰。
2. `npm run build` 通过。
3. 相关 smoke 或脚本验证通过。
4. Git 单独提交。
5. 需要视觉验收时打开 Electron。
