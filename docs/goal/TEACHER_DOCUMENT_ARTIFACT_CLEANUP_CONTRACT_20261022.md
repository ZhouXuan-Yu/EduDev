## 第一性判断

- UI 的审阅卡已经负责展示原稿、修改稿和差异，成品文件不需要再次复制审阅元数据。
- 最终文件应只包含教师可继续使用和修改的教学正文。
- 该规则必须由宿主在写入提案边界执行，不能只依赖模型是否遵守提示词。
- 不能误删教师真正编写的同名教学章节；只有位于文末且同时包含“原内容”“修改后”对照字段时才视为内部预览。

## 修改边界

- 仅在 `textProposalInput` 规范化 `office_create_text.content` 和 `office_edit_text.edits[].newText`。
- 保持 `oldText`、审阅前后文本、差异、审批、版本 CAS、文件写入和撤销规则不变。
- 不新增 IPC、SQLite 字段、依赖、权限、工具或 Agent Loop。
- 历史 change 记录不改写；新提案在落账前使用清理后的正文。
- 普通教学章节使用“本次修改预览”但没有对照字段时完整保留。

## 验收

1. 模拟包含文末“本次修改预览 + 原内容/修改后”表的创建提案，审阅和保存内容都不含该表。
2. 创建提案保留教学正文，并保留一个最终换行。
3. 编辑工具的 `newText` 混入同样表格时，计算后的文件不出现重复空行或审阅元数据。
4. 只有“本次修改预览”标题、没有对照字段的真实教师内容必须保留。
5. `pi-text-change-foundation-smoke`、build、renderer240 和真实资料备课链通过。
6. 真实资料链复核 41 分钟、8 道练习、来源、审阅/文件哈希一致和冷启零模型重放。
