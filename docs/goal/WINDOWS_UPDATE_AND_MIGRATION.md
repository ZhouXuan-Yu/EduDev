# 小智 Windows 更新与换机接续

## 教师接续的交付顺序

1. **先交付换机包和新机接续检查。** 旧机「设置 → 备份与恢复」分别提供同机回滚快照与换机包。生成前列出资料、对话、成果、偏好、个人 Skill 和模板的携带范围，以及遗漏原因。换机包提供可用的包大小和目标空间信息。原有全量备份和新的换机包分别核验，前者保留现有恢复行为。
2. **再交付覆盖更新和回退。** 发布候选保存可核验的版本、架构、安装包摘要、签名结果、支持的升级来源和数据库格式。设置页显示更新内容、兼容性和可选择的重启时机。更新前生成并确认快照可用，安装后校验原工作区。回退按旧程序和对应旧快照成对验收，保留新版期间产生的资料。
3. **最后验收换机后的教学接续。** 以两个隔离 Windows 环境执行 UM-01～UM-09。先验证旧机离线时新机能独立完成恢复，再核对首次进入和恢复就绪后的两种状态。按现有安装验收记录版本和启动路径，保存资料 ID、确认记录和产物摘要的对照。三步分别记录通过和待验项。

### 新电脑第一次打开的状态

| 教师看到的状态 | 可操作行为与判定 |
| --- | --- |
| 准备接续 | 选择本地换机包后，集中看到来源版本、将恢复的内容、预计空间及需重绑项目。目标已有资料时准备独立副本，当前资料还可用。 |
| 可以继续备课 | 激活并首次冷启后，直接在原入口打开已恢复的资料、题本、组卷草稿、对话及课件。旧成果的预览与树状定位指向新机上的同一版本，另存为默认建议新机可写位置。索引仍在重建时提供就绪进度，已有本地内容照常浏览。 |
| 需要补齐环境 | 在状态页汇总模型或连接器重登、外部目录重选和受管工具安装。补齐后回到原任务入口。当前模型、思考档次或能力有变化时明确显示实际值，避免静默降档。 |
| 可以撤销 | 从设置切回原工作区。重启后核对切回前后两个副本的记录，均可再次进入。 |

验收以同一组教学操作及结果为准。资料、确认、已生成文件和可迁移偏好按稳定标识及文件摘要核对。只在源机有默认程序的格式在新机验证可选打开方式，系统应用选项由本机安装决定。对同一份样本分别记录新机首次可用时间和就绪后的耗时，标明硬件、索引和模型环境。

## 发版与换机的交付门槛

当前桌面包版本为 `0.1.0`。备份预检比较应用版本与数据库格式，两个都显示 `0.1.0` 的构建无法仅凭这个结果区分新旧。发版记录须固定每个公开版本的应用版本、源码提交、安装包 SHA-256 与支持的来源版本。兼容测试使用真实旧版安装包和由该版本实际生成的快照。格式不兼容时递增数据库格式版本，并验证旧程序明确拒绝。切回用匹配的旧安装包和更新前快照，更新后新增的资料保留独立副本。

换机页面须把每类内容标成「随包恢复」「需要重新设置」或「新机后台准备」，以验收读回结果为准。

| 分类 | 教师在新机上的通过条件 |
| --- | --- |
| 随包恢复 | 找到原题和原页，继续原对话或组卷草稿，核对原确认记录。模型偏好、思考档次、个人 Skill 和模板按实际生效值核对；不可用项标明具体原因。 |
| 需要重新设置 | 一处汇总模型登录、外部目录和工具依赖，逐项给到设置入口。可跳过当前备课用不到的项目。新机的默认应用由 Windows 决定。 |
| 新机后台准备 | 首屏先能打开已恢复的对话、资料和成果。索引重建时注明尚未就绪的搜索范围。就绪后同一查询命中同一原题与页码。在各机记录首轮与热轮耗时和条件。 |

### 历史成果的换机验收

在旧机从已保存的 HTML、PPTX 和 PDF 进入预览，记录所在分组、版本和文件摘要。在新机断开源盘后，从旧对话和教学成果入口重新进入同一文件，核对树中选中项、预览和实际打开路径均指向新机副本。分别验证系统默认应用、选择其他应用、打开所在文件夹和另存为。另存副本与原件字节一致，随后重新打开历史版本仍能定位原件。对于自选目录，核对已登记成果如何重定位，以及未随包的项目能否在页面上看到原因并重新选择位置。覆盖更新前后复跑同一流程。

本轮已核对版本来源与现有文件入口，新增判定分别纳入 UM-01、UM-02、UM-04、UM-06 和 UM-09。安装覆盖、回滚与异机闭环仍待实测。

## 2026-11-21 备份版本预检

「设置 → 备份与恢复」的新备份记录 Electron 应用版本以及一致性 SQLite 副本的 PRAGMA user_version。检查结果同时显示备份版本和当前版本。文件完整性通过后，较新应用生成的备份要求先安装相同或更新版本。当前读器仅接受已使用的数据库版本 0，后续不兼容的迁移须同时更新 PRAGMA user_version、读器和覆盖升级测试。恢复在复制前检查较新格式，在副本准备结束前再次验证。旧 v1 清单仍按既有目录元数据和数据库实际格式恢复。未引入数据库迁移。

通过实际设置页验收 7 项，覆盖同版备份、独立准备、可恢复的旧清单、较新应用、实际较新数据库、版本信息矛盾和取消。既有恢复底层 8 项和教学文件操作 6 项通过。保留旧程序安装包与更新前数据快照是覆盖升级回退的下一交付项。 [验收入口](../acceptance/CURRENT.md#2026-11-21-备份版本预检)

### 换机包内容核对

现有全量本地备份包含 SQLite 内的默认模型、会话模型和思考档次记录，也可能包含旧版保存的 API Key 或与 Windows 账号绑定的加密凭据。换机包应在备份副本中保留明确允许的偏好，删除凭据字段并清楚显示重绑项。保留完整本地备份供同机回滚。分别测试新写凭据与历史明文旧记录，并核对源库、原快照及历史 Run 无修改。外选文件只迁移已经明确登记并成功备份的成果。个人 Skill、模板和依赖版本是否随包，以清单及新机读回为准。

B 上选择备份后应先看版本和内容，再准备独立副本。新机从正式安装包运行，冷启后按 UM-09 观察旧课件预览、文件树定位、另存去向、首轮和热轮等待；相同教学操作、资料、引用和偏好作为验收。设备和模型服务带来的耗时差异单独留证。

## 教师完成的操作

- **原电脑更新**。在现有「设置」入口看当前版本、更新内容、兼容性和重启提示。安装新版前创建并校验可恢复的本地快照，等正在写入的任务结束或由教师明确中止。重启后继续原教学工作。
- **换到新电脑**。旧电脑在「设置 → 备份与恢复」生成并校验搬家副本。教师通过自己选择的介质搬走完整备份。新电脑安装兼容的小智，选中备份后先看核对结果和需重新绑定的项目，再确认使用新副本。原电脑和新电脑原有数据各自保留。
- **撤销**。换机后可切回新电脑原资料。升级回滚使用保留的旧程序与升级前数据快照，恢复选择前展示旧版本和快照时间，并保留新版中已产生的教学记录供后续取回。
- 首期按一次性迁移及同机更新验收。两台设备继续并行编辑后的同步或合并需要另行确认产品行为。

## 一致性的定义

| 分类 | 目标 |
| --- | --- |
| 业务资料 | 资料库层级、原件及页码定位、题目及答案、跨题源关联、组卷草稿和已交付试卷、学生档案、错题、学习记录、教师确认及修改史都可在新电脑按原入口查看。 |
| 小智对话 | 历史及其顺序、引用、文件版本、任务阶段和检查点、审批历史、已保存的报告和产物保持可追溯。正在运行的本地终端和进程结束于旧机，新机显示可恢复状态。教师从安全检查点明确继续。首开不会重发模型、写文件、提交审批或触发待运行工具。 |
| 熟悉的使用方式 | 可迁移的模型偏好和思考档次、工作台偏好、个人 Skill、已编辑模板与快捷设置保留。依赖相同可用时执行路径一致。窗口尺寸按新屏幕适配，默认应用按新系统关联。已有成果的预览、文件树定位和另存为指向新位置。 |
| 新机确认 | 模型和连接器密钥在目标系统重新输入或登录。外选资料路径、外部目录权限、MCP／工具能力及环境依赖在新机重新验证。审批历史保留，未执行的授权按既定权限合同重新判定。丢失或不可读项目标出名称、原因和修复入口。 |
| 索引和运行时 | SQLite 与原始文件随副本，派生索引和缩略图在目标机重建。展示重建进度、可使用的功能和待就绪项目；完成后用固定检索和引用核对结果。安装时按目标机查验随包与受管依赖。 |

相同版本、相同资料和相同配置下，验收比较的是教学任务、事实、校验结果和操作路径。模型的自然语言措辞、启动耗时以及系统应用列表受实际设备和服务状态影响，分别记录。

## 实施顺序

1. **扩充现有备份及恢复契约**。继续使用 SQLite 一致快照、受控原件和成果清单、文件摘要校验、准备副本与激活指针。为后续格式记录应用版本、数据库格式版本、可迁移配置、所需空间及遗漏。读入旧清单时保留已验证的兼容路径；缺失迁移信息时说明用哪一版本重新备份。点验当前备份对模型凭据、连接器凭据、个人 Skill、模板和偏好的覆盖，迁移包以显式允许的配置字段为准，避免直接复制整份系统配置。加密凭据的占位或清理不得改变源库。
2. **通过新机恢复预检与任务接续**。将可变盘符、用户名和数据根路径映射到新机，保留原历史证据。源盘不可访问时仍能校验已复制资料。包内无权限的路径明确要求重选。目标已有教师资料时先创建独立副本，再确认是否切换；出现空间不足、断开、损坏、版本较新、取消或启动失败时，保留可启动的原数据。
3. **交付可验证的更新路径**。先支持通过受信发行来源获取更新，由用户选择时机，校验签名、版本和候选摘要，并用已有备份链路准备升级快照。验证 N−1 → N，随后验证支持期内的跨版本路径。数据库迁移增量、可重复，遇错回退到兼容程序和升级前快照。应用程序安装路径与资料路径分开。自动下载和增量更新可在覆盖升级和回滚通过后评估。
4. **做独立 Windows 实测**。沿用 QG-09 原安装项并保留结果。使用两个隔离 Windows x64 环境或两个可验证独立系统快照，分别记录 Windows 用户、盘符、安装包哈希和实际运行路径。迁移矩阵按下表执行。受控 source smoke、同机开发版恢复、真实安装升级和异机恢复各自保留结果。

| --- | --- | --- |

恢复完成时按资料 ID、文件版本、来源页和摘要逐项核对。模型偏好、思考档次、模板和个人 Skill 比对实际生效值。外部目录改用 B 的可用位置，旧引用保留来源记录。索引尚未就绪时，先验证已恢复内容可浏览，再用固定问题检查索引完整性。两轮计时复用同一工作区，分别记录首开和后续操作。用模拟损坏、空间不足与迁移中断检查失败提示、恢复入口和原工作区读回。业务数据缺失、引用错误、覆盖原资料或冷启重发任务任一发生，相关组合判定失败。

- 源码基线 4b4ebe4。现有产品具备本地备份、SHA-256 校验、恢复到新目录、确认切换和回退。默认产物与已登记外选成果有独立复制路径。现有备份 v1 清单记录格式和文件完整性，缺少用于升级预检的明确来源应用版本和数据库兼容范围。
