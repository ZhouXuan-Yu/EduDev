# 教师文件预览空间合同（2026-10-22）

## 状态

`SOFTWARE_ACCEPTED`，Goal 保持 `ACTIVE`。本切片只优化资料备课主线的文件阅读与修改体验。

## 教师可见问题

真实资料冷启截图显示：右侧文件面板同时保留文件树和正文后，长备课稿只剩很窄的一列，频繁换行与滚动增加教师定位成本。原有文件树开关只有图标，不容易发现。

## 第一性判断

- 教师打开文件的第一目标是阅读或修改正文，文件树是次级导航。
- 窄面板中同时显示导航和正文会牺牲主要任务空间。
- 打开文件后可自动优先正文，但必须保留清晰、可见、键盘可达的文件列表入口。
- 文件树开关和面板宽度属于临时界面状态，不得写入业务事实、文件内容或模型上下文。

## 修改边界

- `PiWorkspaceFiles`在文件面板宽度不超过 760px 时，打开文件自动收起文件树。
- 工具栏按钮显示“文件列表/收起列表”，保留`aria-pressed`、可访问名称和原有功能。
- 不新增IPC、SQLite、共享契约、依赖、文件权限或模型调用。
- 不持久化`explorerOpen`；关闭再开面板恢复默认文件树。
- 文件预览、版本变化、目录授权、错误恢复、标签和拖拽行为保持原实现。

## 验收

1. 真实 Electron打开文件后，窄面板正文宽度至少为面板宽度减 2px。
2. 工具栏明确显示“文件列表”，点击后文件树恢复，再点可收起且正文不丢。
3. 1366×768、1920×1080、浅色、暗色实际截图无裁切。
4. 聊天输入、文件树、标签、刷新、关闭和发送控件保持可达。
5. 39个实际文字对比样本≥4.5。
6. 目录授权、文件变更、超限、损坏文档、标签切换、重启和归档权限边界继续通过。
