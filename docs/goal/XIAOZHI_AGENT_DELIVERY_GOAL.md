## 4. 每个功能的执行方法

1. 选下一个前置已满足、尚未达标的WP，读取该组全部REQ/AT/FX和当前相关代码、入口、数据。先确认现有能力，优先成熟实现与薄适配。
2. 将WP .01–.06落实到具体修改清单：共享契约、main/Worker、typed preload、当前可操作前端、SQLite/文件、失败/取消/恢复、旧数据兼容、回退与必要验证。不另起平行UI或账本。
3. 连续完成这一功能的主路径和适用边界。先交付真实用户结果，不只增加DAO/IPC/脚本；不因测试困难将功能缩水成文字建议。
4. 做一次必要的相关检查。失败则定位、修复并重验受影响项；已经通过且没有新变更/失败/未决疑虑，不反复重跑同套检查。
5. 当前阶段所有功能对齐后，集中按验收书执行完整用户旅程；一个旅程可以为多条AT取证，不为252条用例机械发252次模型请求。
6. 逐条记录结果并同步“已实现”备注；保留失败与未验，推进下一项。不以“代码已写完”提前结束Goal。

发生中断时先读进度、追踪表及真实文件/账本，继续未完成部分；已保存成果不重做，已完成操作不重放，旧批准/摘要不能作为新权限。

## 5. 避免过度审核与不必要打断

以完成已授权功能为默认行为，按任务书已有边界执行，**不额外扩建安全审核体系**。

- 现有会话已经授权的代码修改、复用、临时测试、合法工具准备、Git提交/正常整合与推送，沿已有授权推进，不反复问“是否继续”“是否允许修改”。
- 常规可逆实现由开发者自行作合理选择；只有实质影响用户结果、数据真源或新授权范围的取舍才需用户决定。不要为了命名、文件拆分或普通实现方式打断。
- 不默认安排独立安全审查Agent、多轮评审会、全库审计、通用合规清单、大型盲评或重复性能跑分。用户未启用子Agent模式时不自动启动子Agent。
- 不新增资料/题目逐条人工批准，不把已有整卷集中确认拆成多轮重复审批；同一任务的必要审阅尽量按明确文件/内容版本集中呈现。
- 本功能确实新增依赖时才检查该依赖的来源、版本、许可、兼容和健康，不因为改一段UI或文档重复审全部供应链；仓库要求的提交前审计在收尾执行一次，不每个小步骤重复。
- 复用既有权限、校验、隐私与文件效果边界。减少审核不等于删除这些业务要求，也不以“完全访问”文案假装已获得任意目录/命令/上传权限。
- 不因旧失败永久禁止用户重新明确提出的新任务；重新读取当前状态，在已有授权内提出新的有效操作。

**仅在实际遇到以下边界时暂停相应动作**：没有覆盖该动作的明确授权；新增真实付费请求/服务或外部发布；不可逆影响真实数据；修改凭证；改变本地优先/隐私/教师正式确认/来源规则；未知所有权且与本轮重叠的脏改动。先完成其他不依赖它的工作，给出具体可审阅结果、缺少的决定及原因，不把局部阻塞当全部任务停止。

本任务旧20次真实模型额度已用尽。新费用授权前先完成代码、合成数据、本地/受控验证及具体试用批次准备；不能借知识库其他线程的额度。必要时一次说明拟发送内容、请求上限和用途，不零散重复申请，不偷偷发请求。

| 验收手册对应AT末“实现备注” | 已实现；验收通过；日期；实际结果/批次及证据位置 |
| CSV对应行 | 实施状态=已实现；验收状态=通过；实际结果/证据/执行时间/源码SHA/运行根/样本版本齐全；备注以“已实现”开头 |
| WORK_PROGRESS及相关状态入口 | 仅汇总真实新增达标项、仍未完成项和下一位置，不把局部通过扩为整组/整阶段完成 |

建议备注格式：

> 已实现｜2026-MM-DD｜AT-E01-01｜实现SHA/验证SHA｜批次/证据路径

若实现与验证SHA不同，两者都记录；证据应能复核当前产物/配置/来源版本，不能只写“测试通过”四个字。没有证据、只完成后端、受控结果不足以支持自然质量/安装结论时，保留“待验收”或“部分实现”，不能备注已实现。

### 6.2 整个功能组与后续回归

一个WP全部承诺的适用REQ达标、相应C项满足且无阻断缺陷，才在任务书功能组与本Goal执行清单末备注“已实现”。个别细项通过可以先标细项，整组保持部分实现。批准不适用单列理由，不当成已实现。

验收失败=失败/待修复；缺环境/授权=阻塞/待验收；没跑=未执行。既有上游功能可复用旧证据，但必须能覆盖本条完整标准和当前兼容范围，不自动批量回填已实现。

已标项后来因相关改动失效，应写“待复验（原已实现，原因/影响）”，保留历史证据；复验通过后恢复已实现，不删除曾经的失败。不得删用例、换更轻数据或降低标准来增加已实现数量。
