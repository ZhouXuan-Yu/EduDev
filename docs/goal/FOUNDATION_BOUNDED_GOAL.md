## 代码与UI分工

- 唯一开发分支：`codex/hana-answer-quality`，复用现分支，不为每个模块另开分支。
- 本会话负责 `shared/`、`main/`、Worker、typed preload和基座测试。**从本指令起不再修改renderer、页面CSS或已冻结设计**；已经完成并验证的T02页面接缝随当前模块交付，后续样式和入口交UI会话。
- 每模块交接列出输入/输出类型、IPC、状态和错误码、真实调用样例、消费者及已知未完项；UI需求只写交接，不代替另一AI修改页面。
- 每模块先提交功能与必要检查，再fetch/整合最新origin/main并正常推送`HEAD:main`及本分支。不得强推、移动其他工作树的已检出分支或覆盖其脏文件。只有docs变化不重启日常软件；修改运行代码后按现授权更新D盘经验证构建。
- 不增加第二Runtime、第二任务账本或逐工具批准。教师对最终教学内容/文件的原确认保留；认可且已授权的依赖准备直接做。仅真实新增外部费用、凭证/权限变化或不可逆用户数据操作才请求必要授权。

## 有上限的执行方式

1. 24条需求和24条AT冻结。每条先登记“已实现/部分实现/未实现”和证据；不把没有验收记录等同于没有代码。
2. 一个模块最多**1轮实现＋2轮定向修复**，六模块合计最多18轮。每轮指修改实现后执行一次相关检查；纯读文档不消耗修复次数。失败现场保留，修复只重跑受影响检查。
3. **总回合硬上限20**：从下一次执行开始，每次自动续作或用户要求继续的工作回合都记总次数（含仅盘点/文档回合），进入时加1；不因压缩上下文、换会话或重新启动而清零。达到20回合尚未DONE必须STOPPED_UNMET并停止工作。模块功能齐后集中验收一次；跨模块最终集成最多**1轮＋1轮定向修复**。总计最多20轮。固定24条通过即结束，不再增加“更智能”“更精美”或额外样本门槛。
4. 每轮更新进度的使用次数和下一条ID。需求变化、费用受限或一次外部工具失败不触发无界重试。
5. 一条完整AT通过后标“**已实现**”，记录源码SHA、实际运行根、命令/输入、结果和证据。只完成工程子项则标“部分实现”，不得把Mock或合成模型输出当自然质量验收。
6. 必要门禁：改动相关领域/契约测试一次；桌面代码构建与现组件门禁一次；关键共享路径改变时一次仓库smoke；收尾diff检查。已通过、未受影响的测试不在每轮重跑。基座AT主要从真实typed IPC/主进程、SQLite/文件和请求回执核对，不因等待另一会话美化UI而反复验。
7. 本期新增付费模型请求预算为0。使用本地受控传输验证实际生产调用链；自然模型A/B另立有费用授权的任务，不作为本期无限等待条件。

## 终止状态

| 状态 | 判定 | 必须动作 |
| --- | --- | --- |
| DONE | 固定24条AT通过，无未关闭P0/P1，模块均正常整合到main，运行版本与交付记录一致 | 出一次最终报告，结束Goal；不继续Backlog |
| STOPPED_UNMET | 某模块3轮已用完仍未达标，或最终集成2轮用完 | 列明确切失败项/现场/已提交范围/下一选择，停止自动实现；不得宣称完成 |
| NEEDS_DECISION | 必须超出本期范围、增加费用/权限、动不可逆数据，或无法安全整合另一个AI的重叠改动 | 交付已完成模块与具体阻点，等用户决定；等待不等于同意 |
| CANCELLED | 用户要求停止或更换目标 | 保存现场与进度并结束，不派生新任务 |

以上是文档执行状态。工具层Goal的complete/blocked/paused按工具自身规则设置，不能用文档状态伪造工具状态。达到停止条件后必须终止自动继续，不能自动开启二期；若需要手动创建新Goal，复制下面目标文本使用本文件四个入口。
