# ACCEPTANCE_CRITERIA — 独立验收标准

## 1. 验收原则

验收由独立 Agent 执行。实施 Agent 的自述、截图或“代码已完成”不能单独作为证据。每项记录：ID、前置条件、步骤、预期、实际、证据链接/日志、状态（PASS/FAIL/BLOCKED/NOT_TESTED）。

## 2. P0 架构与安全验收

| ID | 场景 | 通过标准 |
|---|---|---|
| A-P0-01 | 唯一 Runtime | 不存在第二个 Agent Loop/独立 Planner Loop |
| A-P0-02 | 执行边界 | 所有动态 Provider 经过宿主执行边界 |
| A-P0-03 | 权限越界 | 超出授权范围的文件/命令/网络/MCP 操作被阻断 |
| A-P0-04 | Skill 扩权 | Skill 声明权限不能产生实际 Grant |
| A-P0-05 | MCP 安全 | readOnlyHint 不被当作安全证明；Schema/来源/权限检查有效 |
| A-P0-06 | 外部代码隔离 | 未验证 Extension 不在 Electron 主进程执行 |
| A-P0-07 | 撤销优先 | Provider/Grant 撤销后新执行被阻止 |
| A-P0-08 | 数据外发 | 未授权教师/学生资料不发送到外部 Provider |
| A-P0-09 | 旧 Run fencing | 旧 Generation 的延迟结果不能覆盖当前 Task |

## 3. Capability Protocol 验收

| ID | 场景 | 通过标准 |
|---|---|---|
| C-01 | 核心 ID | 命名空间稳定，外部不能冒充官方 |
| C-02 | 多 Provider | 同一 Capability 可绑定多个 Provider |
| C-03 | Required 缺失 | Resolver 排除 Provider |
| C-04 | Optional 缺失 | 可选用但明确披露 |
| C-05 | Conditional | 按任务条件判断 |
| C-06 | 不兼容 Contract | 不得映射或执行 |
| C-07 | Manifest 篡改 | 哈希/签名验证失败则隔离 |
| C-08 | Provider 撤销 | 不被旧 Snapshot 复活 |

## 4. Resolver 验收

| ID | 场景 | 通过标准 |
|---|---|---|
| R-01 | 权限过滤 | 不合格 Provider 不进入 AI 候选 |
| R-02 | AI 越权返回 | 宿主拒绝不在 eligible set 的 ID |
| R-03 | 用户固定 Provider | 仅作为偏好，不覆盖硬约束 |
| R-04 | 任务内切换 | 可切换兼容 Provider，保留 Task 和成果 |
| R-05 | 长期默认 | 单次故障不改变长期默认；需评估证据 |
| R-06 | 部分能力 | 缺口随 Resolution 和交付信息披露 |

## 5. Pi Runtime 集成验收

| ID | 场景 | 通过标准 |
|---|---|---|
| P-01 | 核心业务 Tool | 既有工具仍保持明确名称/Schema 和行为 |
| P-02 | Dispatcher | 动态 Provider 可由稳定入口解析调用 |
| P-03 | 新能力激活 | 当前任务在安全点获得新能力或安全重建 Session |
| P-04 | Session 重建 | 同一 Task 可关联新 Session 和新 Run |
| P-05 | Pi API | 所有动态工具行为有锁定版本源码/类型/测试证据 |

## 6. Skill 验收

| ID | 场景 | 通过标准 |
|---|---|---|
| S-01 | AI 创建个人 Skill | 纯说明型 Skill 自动 Draft、验证和发布 |
| S-02 | 私有默认 | 个人 Skill 默认仅本人可见 |

## 7. Marketplace / MCP / Extension 验收

| ID | 场景 | 通过标准 |
|---|---|---|
| M-01 | 外部市场搜索 | 多来源结果可规范化并保留来源 |
| M-02 | 候选隔离 | 市场候选不能直接生产执行 |
| M-03 | 可信自动安装 | 来源、许可证、依赖、权限满足策略后自动安装 |
| M-04 | 未知来源 | 进入隔离或审批 |
| M-05 | MCP Schema 变化 | 重新验证，权限变化触发重新审批 |
| M-06 | 凭据 | 不进入 Skill、JSONL、日志或普通数据库明文 |
| M-07 | 离线 | 缓存能力按撤销/有效期策略工作 |
| M-08 | Extension 隔离 | 外部代码不直接进入主进程 |
| M-09 | 撤销/卸载 | 新调用被阻断，状态和审计保留 |

## 8. Task / Checkpoint / Recovery 验收

| ID | 场景 | 通过标准 |
|---|---|---|
| T-01 | Task 跨 Session | Task ID 稳定 |
| T-02 | Run 恢复 | 新 Run ID/Generation |
| T-03 | 应用重启 | 自动恢复状态并展示继续入口 |
| T-04 | 启动诊断 | 只读诊断，不产生写副作用 |
| T-05 | Effect Intent | 有副作用操作执行前持久化 Intent |
| T-06 | 写入后崩溃 | 通过实际状态核对，不重复写入 |
| T-07 | 外部调用超时 | 查询回执/幂等键，不盲目重发 |
| T-08 | Provider 恢复 | 先检查旧 Provider，再选兼容 Provider |
| T-09 | 审批重启 | 待审批持久化并重新显示 |
| T-10 | 审批失效 | 目标/范围/Provider 安全属性变化后失效 |
| T-11 | 教师拒绝 | 不重复申请相同权限，尝试替代路线 |
| T-12 | 多任务 | Task、权限、Artifact 和 Session 不串线 |
| T-13 | 多次重启 | 已提交副作用不重复执行 |
| T-14 | SQLite/JSONL 不一致 | SQLite 任务事实优先，差异可诊断 |

## 9. H-16 规划验收

- 简单查询不强制冗长计划。
- 多工具任务能形成步骤依赖。
- 复杂任务在执行前检查关键能力/依赖/权限。
- 执行失败后能基于实际结果更新计划。
- 规划深度不代替风险权限门禁。

## 10. 页面验收（由 6.1 Terra High 执行）

### Agent 工作台
- 恢复任务数量和状态准确。
- 已完成任务不混入恢复列表。
- 教师能看懂已完成、待继续和阻塞原因。
- 点击继续只启动一个新 Run，不重复创建 Task。

### 审批 Inbox
- 说明操作目的、资源、数据范围、持续时间和拒绝后果。
- 可批准/拒绝；状态持久化。
- 不展示秘密值。
- 不把技术细节强迫普通教师理解。

### 能力中心
- 区分已安装、可用、待验证、需授权、不可用。
- 展示来源、版本和风险详情（高级信息可折叠）。
- 市场候选不能显示为已验证能力。

### Skill 管理
- 个人/团队/官方归属清晰。
- 团队管理员审批状态清晰。
- 版本历史、回滚和来源可查。

页面验收必须基于实际运行界面、关键交互和截图/录屏证据；仅审查设计稿不算通过。

## 11. 回归和质量门禁

- TypeScript 类型检查。
- Lint。
- 相关单元测试。
- 数据库迁移测试。
- IPC 契约测试。
- Tool 调用集成测试。
- Pi Session 集成测试。
- Electron 开发与打包构建。
- Windows 目标环境测试（项目支持范围内）。
- 现有教育核心功能回归：知识检索、题库抽题、组卷、PPT 生成、文件读写。

## 12. 最终报告格式

每个验收项记录：`ID | 状态 | 环境/版本 | 测试步骤 | 预期 | 实际 | 证据 | 缺陷链接`。

最终汇总 PASS / FAIL / BLOCKED / NOT_TESTED。不得将未测试写成通过。P0 任何 FAIL 都不能发布；P1 未通过必须说明是否阻断交付并由产品负责人决定。
