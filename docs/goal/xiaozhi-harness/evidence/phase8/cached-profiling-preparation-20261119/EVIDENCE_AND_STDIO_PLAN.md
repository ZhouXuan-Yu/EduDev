## stdio sharing must preserve independent projections

Existing source anchors are in D:/WorkProject/EduProject-harness/apps/desktop/src/main/xiaozhi-agent:
- mcp-controlled-service.ts:46-48 puts frozenOwner, projections and verifiedFiles in the same forOwner closure. transformInput/healthInput select projection by serverId at lines 92-110. transport rejects projections.has(serverId) at 115 and later installs the projection at 155. Cleanup conditionally deletes only its selected projection at 181.
- capabilities/acquisition/managed-mcp.ts:134-160 creates a new stdio for each authorized call and for each opened artifact tools set. opened is keyed by artifactId, while tools calls the global mcp.tools catalog, not an artifact-filtered catalog.
- mcp-runtime.ts:251-339: each tools() creates/disposes its own clients map and connects every ready/trusted server. Two artifact tools() can therefore hold overlapping clients for the same server. A single shared projections map could cause resource_busy on overlapping transport entry, or an early preparation race before projections.set could overwrite lookup and misdirect transformInput. It must not be shared across these independent lifetimes.

Recommended narrow API shape: keep forOwner(context) as the factory boundary with frozen owner and the existing verifiedFiles map; move only the per-view projection state into a nested createView(). Return a view with fork(): ControlledOwnerStdio. A fork uses the exact same frozenOwner/context and shared existing verifiedFiles map, but creates a fresh projections map and retains its own transport/transformInput/healthInput/cleanup closures. fork must not accept a replacement context or externally supplied Map, and must check the original owner/signal. Give the recursive return a named interface so TypeScript does not infer a recursive-any return.

Inside createManagedMcpProviderRuntime, lazily retain one root view for its original options.context; authorized calls root.scopes. Each independent options.mcp.tools call uses root.fork() in permission(options, fork). Existing opened/clients promises and dispose lifetimes remain unchanged. registerManagedMcpArtifact and production session MCP startup remain independent and unchanged. No runtime-wide/global/cross-Run cache, no client reuse, no source/schema/catalog/Grant/allow memoization, and no change to admission deadlines.

This shares only the existing filename -> fileVersion+expectedSHA verification memo. Every fork binding still re-resolves options.binding (artifact/TTL/revocation/root checks), checkedFile, lstat/type/nlink/size/fileVersion, original owner/signal checks; mismatches run original streamed SHA and post-stat. Different filenames or expected hashes never reuse a hit. Projection copy, destination SHA, exact held-handle native SHA and lease checks remain independent. No single-flight is required; overlapping cold hashes may duplicate harmlessly and preserve existing race checks.

Input/capability mutation: createMcpPermissionContext must still recompute scopes, inputDigest and sanitized summary for every actual call, invoke original PermissionEngine run/assert, then record authority. mcp-runtime must still verify current catalog trust/selected tool before call, re-list actual schema under the resource lock, re-read trusted server state, and call the view's own transformInput before effect. Sharing file validation must not cache source/permissions/input/summary/results, nor replace any of these checks. Runtime secret/schema/revoke mutation retains its existing client closure/lease invalidation.
