## Strict narrow design

1. Add a versioned immutable per-tool-call acquisition completion receipt in the existing SQLite source of truth, for example xiaozhi_acquisition_call_receipts_v1. Primary identity is runId+generation+callId with explicit sessionId/taskId; the payload includes schemaVersion, original tool=capability_prepare, candidateId/hash, requirementsVersion, contract inputDigest, operationId+expected final revision+document hash, plan/artifact IDs and immutable hashes, outcome phase, exact approval/request and native execution evidence references, createdAt, and document_hash. Validate schema/limits and original row hash on every decode. No arbitrary result body is the proof.
2. Add the original callId to AcquisitionContext for tool-origin calls; retain an explicit absent/none form for existing non-tool UI origins. Propagate it from production-host acquisitionContext(id,callId) into service/register/native metadata. Receipt creation requires the exact admitted original capability_prepare ToolReceipt/Effect identity and current original owner/task/requirements version, not just an active session. An unrelated UI prepare cannot certify a tool call.
3. Final operation update and immutable call receipt must commit atomically through the existing serialized Sql transaction/CAS lane. Existing artifact/Registry commits may precede that final transaction; a crash between them and final receipt remains unknown. Do not resolve a missing final receipt merely because the current artifact is ready.
4. Persist only two initially supported proven outcomes: ready and known waiting_approval. A waiting approval is a known completed attempt at an authorization boundary, not capability success and not a claim that no local metadata changed. Preserve original tool.success=false/ready=false/approval state. ready still requires the original full package/binding checks, trusted schema and real function probe.
5. Tie every native/probe receipt used as proof to the same original call/attempt, owner (all four fields), operation and artifact. Existing MCP audits contain owner/server/artifact but no parent tool call; add a main-owned acquisition call/attempt reference to intent/terminal/probe records and collect exact executionIds. Do not scan all successful jobs of an owner and assume they belong to the call. The native wire protocol need not change; main-side audit correlation can carry this field.
6. A known waiting_approval receipt must name the exact persisted original approval/request digest and original requested scopes, with no running helper or unverified projection/stage cleanup. Pending dependency before native start can be proven via its exact original request and no dispatched execution. Pending function approval after discovery requires all named original job terminals/cleanup. Unmatched/partial copy, unknown job, cleanup_required, cancellation, crash or ambiguous shared acquisition subscriber stays uncertain in this first fix.
7. A ready readback must verify original call receipt hash/identity, exact finalized operation revision/document snapshot, artifact recipe/plan/files/binding hashes and exact trusted server/schema/Registry binding, exact original health/function proof and closed native cleanup. Do not rehash the whole 90MB Node inside the generic writer transaction: use the original verified file/probe/native evidence and cheap exact file-version/identity checks where needed; changed pins/versions refuse proof. Narrowly refuse changed/unavailable domain facts rather than guessing historical equivalence.
8. A specialized acquisition reader plugs into existing createRecoveryEffectReader before the unrelated tool fallback. It returns matched only for a verified bounded completion receipt, uncertain on mismatches/missing proof, not_checked for unrelated tools. Existing Journal normal settlement and explicit continuation/recheck use it unchanged. matched proves the attempt's persisted outcome; it does not convert waiting into ready, revive Grants or authorize the next action.
9. Do not loosen generic Effect transitions. A fully proven ready/known-waiting executing Effect can use existing committed settlement, or reconciled on explicit continuation after a crash. Original ToolReceipt.success preserves ready vs waiting. Proof reference/digest must contain the typed receipt phase so public recovery cannot imply a waiting request completed capability preparation.
10. Concurrent distinct tool calls or shared running acquisition promises must not borrow another call's proof. Either persist an explicitly validated per-call subscriber receipt to one canonical attempt, or conservatively keep unsupported aliases uncertain. Choose the smaller safe design after inspecting the existing running map; no unbounded redesign in this contract.
