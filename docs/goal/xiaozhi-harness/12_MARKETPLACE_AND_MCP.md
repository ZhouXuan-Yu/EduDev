# 12 — Marketplace & MCP

## 1. 市场策略（H-13）

外部目录聚合 + EduDev 自有市场。外部目录负责发现候选；EduDev 市场负责规范化、来源与许可证信息、兼容性、风险评估、验证、缓存、推荐和发布治理。教师可以浏览，小智可以自主搜索。

## 2. 发现来源

优先研究 Official MCP Registry、Glama、PulseMCP、GitHub、可信厂商目录等。具体 API、条款、可用性和维护状态在实施时重新核实；不得假设市场目录等于安全认证。

## 3. MCP Acquisition Pipeline

搜索 → 候选规范化 → 发布者/仓库核验 → 许可证检查 → 包/镜像哈希 → 依赖和运行方式检查 → 工具 Schema 分析 → 网络/文件/进程/秘密权限分析 → 隔离测试 → Permission Policy → 安装/连接 → 功能测试 → Registry 注册 → 健康监测。

## 4. 安装策略（H-14）

来源可信、许可证允许、依赖可控、权限符合当前用户模式和明确授权时可自动安装。未知来源、许可证不清、不可审查安装脚本、权限超范围或数据外发不明时进入审批/隔离，不得自动生产激活。

## 5. MCP 特别规则

- Server 可提供多个 Tools/Resources/Prompts；按单项 Tool 建立 Capability Binding。
- Schema Hash 变化需重新检查；新增写能力/权限范围变化触发重新审批。
- `readOnlyHint`、`destructiveHint` 是提示元数据，不是安全证明。
- MCP 凭据放安全密封存储，只向对应 Provider 注入必要引用。
- 本地 MCP 优先隔离进程；远程 MCP 检查身份、传输、域名和数据出站。
- 连接成功、Schema 合法、功能正确、安全可信是不同验证结论。

## 6. EduDev 自有市场

统一呈现名称、描述、发布者、版本、来源、许可证、兼容性、依赖、权限需求、验证状态、更新时间、安装状态和撤销状态。普通教师界面简洁，高级用户可展开技术详情。

## 7. 离线

缓存官方签名目录和已验证包元数据；离线可使用已缓存且未撤销的本地能力。新外部资源需要联网验证时标记待验证，不伪装成 Ready。

## 8. 验收

可从多个来源搜索；候选不会自动执行；可信策略自动安装；未知来源进入审批；Schema 变化能识别；凭据安全；撤销阻止新调用；离线缓存可用。
