## 4. 实现和修复的轮次上限

每阶段固定执行：一次实现 → 一次验收 → 如有失败，最多两轮定向修复及受影响项复验。

- 每一轮只能修复当前阶段验收明确失败、此次新引入的回归或权限/数据保护缺陷。修复记录关联 A编号、复现、根因、文件和证据。
- 一轮结束时一次性列齐已发现问题再修，禁止把一个已知问题人为拆成无限小轮；同一失败最多修两轮，不改名重置计数。
- 若发现新回归，仍在当前阶段这两轮内处理；阶段推进不会清空未解决问题，也不能通过新建会话重置计数。
- 已通过且没有新变更影响的项不重复打磨。只有集成改变了其代码/依赖、出现新失败或证据构建不一致时才复验。
- 两轮后必选项仍未通过，输出BLOCKED并停止该合同实施；不能宣称完成，也不能无限追加修复。S4发布最终报告时保留失败证据，不覆盖首次失败。

这里的 BLOCKED 是本任务书的人工交接状态；不自动调用运行环境的Goal状态工具。若实际创建了自动Goal，还须遵守其独立状态规则，不能用本段绕过工具阈值。

## 5. 工程、业务和视觉门禁

从实际 package.json确认适用命令，至少执行桌面构建、类型检查、可用Lint、renderer组件回归、本次相关模块/真实Electron路径；改变关键用户路径时执行仓库要求的 smoke。脚本不存在须明确记录，并使用等价验证，不能写成已运行。

默认命令入口是 `apps/desktop`：`npm run build`、`npm run test:renderer-components`；类型、Lint、模块脚本按当前仓库核实。仓库运行 `git diff --check`，提交前依赖审计按根工程规则执行；已存在审计风险记原状与差异，不擅自升级全部依赖。现有失败只在确证无关、未被本轮恶化时登记为基线遗留；本轮必选验收不可归入基线豁免。

真实Electron至少覆盖1366×768、1920×1080、800×768；浅色，Hover/Focus/Pressed/disabled、展开/收起、运行/最终/失败/停止/审批、长内容与空态。截图绑定源码SHA、构建指纹、viewport、DPR、主题和状态。系统字体/缩放差异允许，核心布局/操作/状态/组件外观不允许未经批准变更。

生产草稿、学生/资源上下文与审批验证要有重启/readback；来源修改使核对失效。正式导出用明确测试资料，实际打开验证；浏览器HTML打印、测试mock或数据库有一行记录都不能替代正式用户闭环。

性能只评价本次UI：同机同数据记录首屏可交互、长对话滚动/流式和典型选题页操作的前后观察及包体差异；不增加付费模型基准、不宣称P95改进。新增重复监听/重复请求、流式闪烁或主线程持续阻塞须定位修复；缺少可重复数据如实说明，不伪造数字。

## 6. 仅有的两个收束出口

**DONE：工程结项。** 必须同时满足：

1. A01–A36全部PASS且证据来自最终有效构建；工程门禁没有本轮新增失败。
2. 旧功能保留表、数据/权限/兼容性检查完成；无本轮引入的阻断/严重缺陷。
3. 正常整合最新 `origin/main`，无强推；冲突逐项核对；推送后确认远端包含交付提交。若远端继续前进，只需证明交付提交被包含，不要求永远和HEAD相等。
4. 启动供验收的真实窗口，记录实际运行源码、SHA和构建；最新版以实际运行根为准，不由快捷方式名称推断。别人工作树仍在写入时不擅自更新其目录；无法安全交付窗口则不能把A36标PASS。
5. 输出完整最终报告，明确“工程验收通过、等待用户试用反馈”；用户已批准设计不代表功能自动通过。报告后停止，不以等待用户持续满意为由保持无限自动执行。

**BLOCKED：有限执行后移交，未完成。** 硬依赖缺失、协作写入无法隔离、环境/验收不可运行、或两轮修复后仍失败，均列明：具体A编号、已完成提交、失败证据、已尝试次数、唯一需要的外部动作和恢复位置。该状态绝不表述为UI已全部实现。用户批准解除依赖或明确新的修复合同后才继续，不能自动开后继任务。

一般非关键新建议放合同外列表。它们不能阻止已全部通过的本合同结项，也不能掩盖必选失败。
