| 最终 HTML | 本目录 `ideal/`，源码指纹见 evidence/report.json | 离线布局、控件和内存状态、双尺寸截图 | 真正导入、组卷、写文件、模型、数据库与权限已实现 |

DeepTutor 单次合成请求：首次阶段事件约 19.4 秒、首次工具约 20.0 秒、首次 content 约 30.5 秒、done 约 68.3 秒。content 可能是公开工作说明，不能当作最终正文首字；界面显示 56 秒与全请求时长口径不同。该样本证明事件链路，不证明它比小智更快。脱敏报告见 [deeptutor-report.json](ideal/evidence/references/deeptutor-report.json)。

OpenMAIC 本次默认大纲等待倒计时后自动继续，即使自然语言写了“先等我确认”，也不是结构化流程约束。真实生成与服务端 completed 已观测；新浏览器上下文不能用原run地址重开，不能宣称课堂持久恢复已验收。小智必须采用明确教师审核状态与既有持久版本链，不只在提示词里加一句等待。脱敏报告见 [openmaic-report.json](ideal/evidence/references/openmaic-report.json)。

## 核心差距、根因与设计决定

| 编号 | 已知问题与教师影响 | 根因或待验证原因 | 最终决定 | 开发验收 |
| --- | --- | --- | --- | --- |
| G01 | 用户反复看到空过程、泛化状态或正文夹杂过程，不知道小智实际做了什么 | 展示状态与业务事件混用；第一段文字不一定是最终正文；真实当前 main 映射仍需执行 AI 核对 | 公开说明＋真实工具是默认过程；状态只是状态；使用显式最终正文边界 | UI-CHAT-01～06 |
| G02 | 执行结束仍未收起，用时在下方，工具图标不能区分 | 折叠绑定整轮网络结束、局部组件状态或错误阶段；计时无统一定义 | 最终正文开始时整段收起，上方冻结执行用时；读/搜/写/执行各自图标 | UI-CHAT-02/03/05 |
| G03 | 组件接入后外观失真、不同页同类控件不一致 | 已知全局样式与多设计系统冲突风险；具体获胜选择器须真实 CSSOM 取证 | 恢复组件边界，外层统一布局；内部保持安装版本的官方设计 | UI-BASE-01～04 |
| G04 | 空白页重卡片、常开右栏和重复入口竞争输入注意力 | 信息架构按功能堆砌，而非当前任务 | 输入优先、轻量入口、右栏提示后显式打开，四主目的页 | UI-HOME-01～04 |
| G05 | 资料原页、识别结果、校正和技术记录同屏过长 | 文件管理、派生知识、任务诊断缺少层级 | 列表组织＋资源详情；概要/原页/题目/笔记；技术记录按需 | UI-KB-01～06 |
| G06 | “引擎就绪”易被理解为“资料可以检索” | DeepTutor 实测引擎就绪但索引失败；小智应避免同类混淆 | 区分原件可打开、收录任务状态、检索可用范围、题目待核对 | UI-KB-03/04 |
| G07 | 组卷条件、来源、教师确认和文件交付容易脱节 | 一次生成被误当作全流程完成；来源变化未必使旧确认失效 | 保留蓝图和三模式，分蓝图/逐题核对/确认与交付；缺题不暗补 | UI-PAPER-01～06 |
| G08 | 课件生成后仍需教师自行拼装课堂活动 | 文件交付与课堂使用分离 | 新增独立提案：课堂安排→互动预演→检查理解→教师核对 | UI-LESSON-01～04，后置独立阶段 |
| G09 | 学生页重复入口多，证据与选中学生上下文不突出 | 页面按模块平铺 | 先选学生，记录/错题/计划/复盘/概览同一上下文 | UI-STUDENT-01～03 |
| G10 | 设置说明过密，日常与诊断混合 | 配置重要性与生效范围不分层 | 日常/高级；分组就近保存；权限与失败提示不隐藏 | UI-SETTINGS-01～03 |

以上根因有证据等级之分：用户截图/反馈确认现象，源码确认职责边界，执行 AI 必须在正式最新构建复现才可定位为当前代码缺陷。不要按这张表盲改旧分支。

## 借鉴什么，保留什么

| 参考 | 可吸收的优势 | 小智的取舍 |
| --- | --- | --- |
| ChatGPT Projects | 对话、资料与长期任务上下文归在一起 | 教学空间仍是会话组织，不自动扩大目录权限；保留本地资料与教师控制 |
| Claude Artifacts | 对话负责提出修改，成果独立预览/编辑/导出 | 右栏按需，不因普通工具抢开；Word/PDF/PPT/HTML 继续走原有版本与写入链路 |
| DeepTutor | 公开过程、工具、资料引用、最终回答阶段分离；按最终标记收起；资料详情与任务可回看 | 不复制默认完整推理展示、不铺七种后端引擎、不照搬学生端多模块导航 |
| OpenMAIC | 先审大纲，再生成 slide/quiz/interactive/pbl；课堂检查与互动；任务持久化、失败保留产物 | 教师预演优先；默认不新增多代理角色和自动播放；不重建 Pi Runtime，不另设任务真源 |
| Zotero / Notion / Dify | 文件组织与标签、有效版本、检索与维护状态分开 | 保留小智的原页证据、题目来源、教师校正、本地存储与现有题库 |

本轮没有移植参考项目源码。后续如复用代码，单独核对 LICENSE、依赖与维护边界；借鉴交互不等于整仓引入。

## 页面用途与功能保留清单

| 页面 | 教师要完成的工作 | 首屏与迁移 | 保留功能 / 不允许损失 |
| --- | --- | --- | --- |
| 问小智 | 给出需求、跟进执行、拿到可核对结果 | 欢迎语＋现有输入组件；过程与最终正文分离 | 会话草稿、附件、权限/技能/命令/模型/思考强度、排队/停止/恢复、历史与空间 |
| 资料库 | 找到、核对和复用真实资料 | 分类/目录/标签/状态/文件列表；详情按对象展开 | 原件/目录、OCR与两遍原文、题目与参考答案、校正、归档、队列/重试/停止、原有数据路径 |
| 教学文件 | 管理已生成/已导入的教学成果 | 列表＋就近创建/预览 | 文件绑定、编辑版本、预览、导出、恢复和来源定位 |
| 备课本 / 讲义 / 题本 | 组织课堂与教材内容 | 页内标签及内容编辑，减少重复卡片 | 原有 CRUD、草稿、题目结构、来源、教师修改与版本 |
| 智能组卷 | 按条件选题，核对后交付正确版本 | 蓝图→逐题核对→交付 | source_only/hybrid/ai_original、配额/难度/知识点、题组上下文、历史比较、拒绝/确认、六种导出选择 |
| 学生工作台 | 围绕具体学生安排教学 | 搜索/学生列表；选中后页内视图 | 档案 CRUD、查找/录入、证据时间线、错题与练习、计划、复盘、概览；不制造掌握率 |
| 设置 | 连接服务、控制资料权限与恢复数据 | 日常与高级分层 | 模型/能力/联网、技能、MCP工具、目录权限、偏好、诊断策略、归档备份恢复 |

新的“课堂设计与预演”是能力增量，不能为了复现 HTML 删除原备课本；先核对现有预览/互动 HTML 能力，缺少接口的内容单独排期。

## 本轮保留的未验证边界

设计稿不是当前生产应用截图。本轮没有真实 Electron CSSOM、原生 IME/DPI、知识库大规模检索、生成题正确性、打印版式、备份恢复或教师班级试用验收。模型响应样式是否受提示词影响，需执行 AI 以同模型、同输入、同上下文做正文输出对比；不能靠 CSS 去掉所有列表，也不能强迫所有回答为散文。
