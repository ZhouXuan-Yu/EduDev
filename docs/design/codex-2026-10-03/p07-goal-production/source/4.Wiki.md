## 项目背景

前期用户不是大型学校，也不是完整 LMS 管理方，而是独立教师、小微教研团队或小型工作室。产品必须轻量、可演示、可本地运行、数据安全优先。

## 核心业务口径

- 本地优先：题库、学生档案、错题历史、附件默认保存在用户本机。
- 脱敏上云：云端模型只能接收脱敏后的题目文本和必要上下文。
- 教师可修正：OCR、模型输出、题目解析、复盘报告必须给教师保留修正入口。
- 强约束输出：DeepSeek 或其他模型返回应走 JSON Schema 或等价校验。
- 先完成教师真实闭环再扩展：后端、IPC、前端入口、失败状态、数据回读、重启和 Electron E2E 必须同步完成，不以演示页或低层 smoke 代替可用性。

## Book Workspace 适配口径

- Omni-Edu 的 DeepTutor Book Workspace 对外产品名为“专题讲义/单元备课包”，不是学校级 LMS；book/chapter/page/block/source 是本地 SQLite 五层实体。
- 讲义内容块支持 `text/chapter/quiz/card/figure/concept_graph/prompt` 等受控类型，C04 先完成结构与健康检查，渲染/导出在 C05 扩展。
- `inspect_teaching_book` 只读、local-only、bounded；sourceRefs 用于可追溯证据，来源删除或指纹变化必须可回读为 missing/stale。

## 最终双业务闭环

```text
教师资料 -> 解析与索引 -> 题库/知识库 -> 按蓝图组卷 -> 教师确认 -> 试卷与解析
学生错题照片 -> 本地 OCR -> 教师校正 -> 错因/知识点 -> 相似或变式题 -> 针对性练习
```

错题训练中的三元题组目标：

- 原题或错题：定位学生当前问题。
- 相似题：训练同一知识点或同类错误。
- 变式题：检查迁移能力和真正掌握情况。

## 小智 AI Harness 长期口径

- 小智是面向老师的教学决策与内容协作助手，不是学生端万能聊天机器人。
- 小智先识别任务路由，再按路由读取最小必要上下文；不能默认把当前学生的全部近期数据塞进每个问题。
- 稳定 system 规则、route 专属规则、动态上下文、工具 schema 和输出 schema 分层维护。
- 学生相关结论区分事实、推断和未知，重要判断关联真实来源；不自动形成永久学生标签。
- 工具注册、工具可用和工具已调用是三种状态；UI 只展示真实执行轨迹。
- 读取、草稿、写入使用不同权限等级；写入学生档案或报告前必须由老师确认。
- 模型回复使用版本化结构契约并在本地校验；产物状态由真实文件生成结果决定，不由关键词推测。
- 教育脚手架只在辅导、讲解和掌握检查等 route 中启用；教师知识问答和工作台操作应直接高效回答。
- 小智只展示可验证的 route、上下文、工具和边界摘要，不展示模型隐式推理或 `reasoning_content`。
- P0 harness 已接入确定性 router、subIntent、按需上下文、只读工具注册表、Agent loop trace、DeepSeek JSON Output、本地 `xiazhi.reply.v2` schema 校验和 100 条 router/subIntent/tool eval。
- 当前 8 类 route 为：`general_qa`、`student_diagnosis`、`error_analysis`、`practice_design`、`lesson_design`、`report_draft`、`knowledge_retrieval`、`workspace_help`。
- 当前工具执行器覆盖真实只读上下文读取：学生引用解析、学生档案、学习记录、附件元数据、老师知识库、知识图谱、本地题库相似题；写入动作仍必须走确认队列，不得声称已自动保存。

- `npm run test:ai-harness` 是小智 route / subIntent / 工具白名单变更的本地门禁，当前应保持 104/104 通过。
- 目标架构和后续实施路线以 `docs/22_XIAOZHI_EDU_AI_HARNESS_PLAN.md` 为准；该文档是小智教育 Agent 完整进化总纲。

## 小智 Tool Calling v1 当前口径

- 发给模型的工具结果必须 bounded；超出工具 `maxOutputChars` 时标记 `truncated=true` 并只给 preview。

# DeepSeek JSON Output 恢复契约（2026-08-12）

- 正常最终请求：`response_format={type:'json_object'}`，无工具，输出上限 8,000 tokens。
- 可恢复条件：首个 choice 的 content 为空，或 `finish_reason=length`。
- 恢复动作：最多一次 `temperature=0`、无工具、8,000 tokens 的压缩/重生成请求；不得新增事实与工具调用。
- 最终真源：恢复后的文本仍由 `parseStructuredReply` 执行 `xiazhi.reply.v2` 语法与语义校验；本地 `jsonrepair` 只处理 64,000 字符内的完整对象外壳，不修复截断语义。
- 公开观测字段：`finishReason`、`contentPresent`、`jsonRecoveryAttempted`、`jsonRecoveryReason`。连续空 content 返回明确 provider 错误。
