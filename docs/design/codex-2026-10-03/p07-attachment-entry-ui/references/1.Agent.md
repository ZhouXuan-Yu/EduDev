## 禁止事项

### E07/E08 新增禁止事项

- 不得把 Deep Research dry-run、来源标题拼接或 Mermaid 字符串生成伪装成联网研究、已核验引用或可执行图表。
- 不得为了命中“可视化”关键词覆盖显式讲义/题本路由；显式工作区意图优先，新增关键词必须加入 router eval 防回归。
- 研究和可视化工具不得携带学生上下文、原始附件、外部 URL 或写入副作用；结果必须标注证据边界、未知项和教师复核要求。

### C05 高级 block 规则

- 讲义编译器不得执行 `interactive`、`animation`、HTML、iframe、SVG event handler、JavaScript 或本地文件路径；只能安全降级并提示受控查看器/教师复核。
- `code` block 只允许 bounded fenced text，禁止把“代码可展示”解释为“代码已运行或验证”。
- 新 block 必须同时具备共享类型、运行时 renderer、异常 fallback、对抗性 smoke 和回归记录，不能只增加类型声明。

### E15 复习调度规则

- 复习调度必须是主进程纯函数，输入仅限显式知识点与正确/错误证据；不得从自由文本推断掌握度或在 renderer 侧计算。
- 间隔序列、连续正确/错误回退和优先级必须复用固定 scheduler；epoch due 判断不依赖机器本地时区，timezone 只作为展示元数据。
- `get_review_queue` 只读、local-only、bounded，不写 `learning_records`，不返回原始题干/答案；任何掌握度写回仍走教师确认。
- 普通记录标题、摘要或自由文本不得创建知识点；只有显式结构化 `metadata.knowledgePoint` 或受控 mastery 标签才可进入 scheduler。
- quiz/grade 写回必须保留 snapshot 中知识点的显式 `knowledgeType`；禁止用通用 concept 默认值把 procedure/memory 重新分类，否则会绕过 `mastery_assess` gate。
- 新增 scheduler 或 review queue 必须同时更新 route/subIntent/tool eval、确定性/时区/恶意输入 smoke、native tool log 和四份协作文档。
- E15 提醒只允许在应用打开时从 SQLite `learning_records` 重算 bounded 摘要；不得新增 reminder 队列表或后台 cron 真源。renderer 只能展示/跳转，不能确认、删除或改写复习证据。

- 禁止使用不存在的包别名，例如未配置或未安装的 `@heroui-pro/*`。
- 禁止只做结构相似的自制占位替代本地 HeroUI Pro 源码。
- 禁止硬编码 API Key。
- 禁止在 renderer 直接访问 Node API。
- 禁止把临时猜测写成已确认事实。

### 2026-08-11 增量约束：普通问答入口与错误证据

- 普通 AI 页面提交必须进入 `runDeepTutorConsole`，由 DeepTutor AgentLoop 统一承载；页面不得再把旧的固定 `runDeepSeek` 流程当作默认入口。

### 2026-08-11 增量约束：可暂停 AgentLoop 与用户输入

- `ask_user` 是宿主拥有的本地工具；sidecar 只能发出 `xiazhi.user_input.request.v1`，不得自行假设答案或直接读取 renderer/SQLite。

- 应用重启后，`waiting_input` checkpoint 必须可由主进程回读并展示；回答先原子 claim checkpoint，再由安全恢复子 run 接管并保留 `parent_run_id`，不能伪装成原 sidecar Promise 已跨进程恢复。
- UI 可以显示补充信息卡片，但只能显示 prompt/questions，不得显示 raw hidden reasoning；提交后重新进入 `running`，最终以真实 `done` 事件收敛。
- DeepTutor capability 的上游结果必须经过 main-process schema/confirmation 边界；dry-run 只能证明 vendored pipeline 与持久化链路，不得当作 live provider 或生产质量证据。
- Mastery/掌握度只能基于明确的知识点与正误证据计算；自由文本记录必须标记为 unknown，不能为了生成百分比而猜测掌握度，也不能让 DeepTutor LearningStore 成为 Omni 学生数据的第二真源。

- `mastery_status` 的审计事件只能记录 bounded result keys 与 `rawRecordsIncluded` 等安全摘要；不能把完整题干、答案或学生记录正文写入 sidecar/事件流。
- Mastery 互动题必须走 `ai_mastery_questions` 私有表：公开 checkpoint 只允许 questionId/stem/options，expectedAnswer 永远不能进入 renderer、checkpoint 或 sidecar event；评分必须校验已提交答案与 question row 一致，并幂等阻断重复写回。
- `mastery_quiz.questionCount` 最多 5 道，按 SQLite 创建顺序形成单一连续队列；同一学生存在 pending/answered 题时不得创建第二组，评分必须逐题推进，重启后仍按 oldest-first 恢复。
- `mastery_assess` 仅允许 concept/design 知识点，procedure/memory 必须走 quiz/grade；`mastery_build` 必须全量校验模块和知识点，禁止静默丢弃坏节点，并通过 `mastery:getPath` 做主进程回读。
- `mastery_assess` 与 `mastery_build` 只允许生成 `save_mastery_state` 待确认变更；任何 `mastery_attempt` 或 `ai_mastery_paths` 写入都必须经过教师确认并以主进程 SQLite readback 为准。能力验收运行 `npm run test:deeptutor-capability-evals`，不得把无 API Key 的 dry-run 当成 live 通过。
- sidecar 异常退出或 turn 超时必须 fail-closed：活动 run 写入失败/超时 guardrail 并完成，挂起 checkpoint 取消，内存 binding 清理；正常 stop 不得重复执行 crash recovery。恢复验收使用 `npm run test:deeptutor-recovery`，性能 dry-run 不得表述为真实 provider SLO。
- 掌握策略必须区分 `evidenceKind=quiz|assess|unknown`：concept/design 只能由教师确认的 assess 正确证据通过定性门禁；`mastery_status` 对外只暴露 bounded policy 元数据，不得把完整 due-review 或原始学习记录写入事件流。
- Mastery 待作答状态必须以 SQLite `ai_mastery_questions` 为真源：`mastery_status` 只公开最近一题的 bounded projection（不得含 `expectedAnswer`/答案），重启后仍可恢复 `pending/answered`；`mastery_grade.questionId` 可省略但只能回退到当前绑定学生，跨学生题目必须在状态校验前 fail-closed。验收使用 `npm run test:deeptutor-mastery-pending`。
- E16 学情分析必须是只读、可重算的统计层：日期使用 UTC 日历边界且跨度不超过 366 天，跨学生请求必须 blocked，空数据必须显式 unknown；报告窗口和来源 ID 通过安全元数据绑定 confirmation，不能用默认日期覆盖老师指定范围。
- E14 错因分类必须优先复用 DeepTutor 四类 taxonomy，但证据不足只能输出 `unknown`；空答案、粗心、概念/理解/应用信号不得被同一规则吞并，应用错误和未知需标记教师复核。分类工具只读、结果 bounded、重算指纹不得包含原始正文，不能自动写入学生档案。
- E17 Vision Solver 只能生成教师预览草稿：默认不上传原图或返回本地路径；GeoGebra 命令必须过白名单、脚本/URL/隐私文本阻断，拒绝命令不得原样回显；无图必须正常结束为 `no_image`，不伪造几何事实。
- R13 附件探索必须复用 DeepTutor `source_manifest/read_source` 的按需原则：只允许当前绑定学生记录上的 attachment handle，优先读取脱敏 OCR 片段；不得读取任意路径、原始文件或未授权 attachmentId。无学生、无附件、无匹配文本和未解析 OCR 均须 bounded blocked/unknown。验收运行 `npm run test:deeptutor-attached-source`。

### C05 Renderer 规则

- C11 L1 记忆只认 Omni SQLite 的 `ai_agent_runs`、`ai_agent_events`、`ai_tool_runs` 为唯一真源；`inspect_memory_trace`/IPC 只能返回 bounded 阶段、状态、工具名和证据键，禁止 prompt 原文、事件 detail、学生正文和隐藏推理；显式缺失 run 必须 fail-closed，L2/L3 不得冒充已完成。
- C12 L2 记忆必须按 surface 保存为可编辑条目和修订历史；候选摘要只能由本地 run/event 证据派生，AI 不得直接写正式记忆；教师采纳/编辑必须经过 typed IPC、证据引用校验和版本号乐观锁，禁止 raw prompt、hidden reasoning、学生正文及绝对化掌握结论进入条目。
- C13 L3 只能综合 active L2 条目到 recent/profile/scope/preferences 槽位；候选必须只读且等待教师采纳，正式 L3 写入仍需来源 surface allowlist、文本边界、readback 和版本锁；不得把 L3 综合误当学生事实或自动升级上下文权限。
- C14 记忆证据图只能是 bounded、只读的 `L3 -> L2 -> run/event` 投影；节点只保留短标签/状态，禁止复制原文、prompt、detail 或 hidden reasoning；图工具必须继续受 `memory_synthesis` allowlist 与节点/边上限约束。
- C15 记忆治理报告必须显式声明 AI 不可写、active-only 图查询和悬空 evidence ref 数；停用/删除不能重新进入 L3 综合，任何“治理通过”都必须以 SQLite 回读为证据。
- C03 题本 renderer 只能展示 `question_bank_items` 的 canonical 正文与 overlay 元数据；搜索/分类/收藏必须走 preload→main，收藏带版本锁，分类删除为软删除，冲突不得覆盖老师新修改。题本 UI 的空结果和错误必须给出可恢复提示，不能伪造题目或批量迁移已完成。
- 教师从题本 UI 录入题目时只允许 `local_bank` 或 `teacher_resource` 来源；`generated` 必须来自可审计的小智产物链。操作错误不得清空已经 readback 的题目列表，空题干和 stale version 必须零写入并保留可见错误。
- 记忆治理 renderer 必须通过现有 `aiMemory:*`/`aiMemoryL3:*` typed preload 工作：候选生成不得写库，采纳/修订/停用/恢复/删除必须以 SQLite readback 为成功条件；版本冲突要阻止覆盖并保留上次成功读取的数据。deleted L2 在没有专用恢复契约时只做只读审计，不得伪造恢复按钮。
- 附件 Electron 自动化不得再用 SQL 直插冒充用户导入。受控 dialog 适配只能在 `app.isPackaged=false` 且显式 E2E 开关下启用，输入必须是有界绝对路径队列；生产/打包路径继续调用原生 dialog。验收必须从导入按钮开始，回读复制目标、大小、SHA-256 和 SQLite，取消必须零写入。
- C05 讲义页面只能通过 `teachingBook:*` preload 获取主进程编译的 Markdown preview；预览 `writesFile=false`，未知 block fallback，stale/missing source 必须警告。只有教师明确点击导出后才写 `document_artifacts`，并以 status/filePath/fileSize/contentHash readback 作为成功条件。
- PDF/DOCX 基础导出必须保留 Unicode 文本与标题/列表/代码层级，并经真实文件字节和 `document_artifacts` readback 验证；复杂分页、图片、动画或 Office 版式不得凭 smoke 伪称高保真完成。
- 本地数据备份必须先复制到源数据目录之外，再生成 `omni-edu-backup-manifest.v1.json` 并逐文件 SHA-256 回读；缺失、篡改、额外文件和非法清单都必须 fail-closed。验证成功不等于自动恢复成功，不能在没有恢复演练时宣称灾备完成。
- R10 预算与续写：主进程必须把 `maxEvents` 归一化到 `1..256`，按 turn 串行计数 sidecar 事件；超限写入 `budget_exhausted` guardrail、取消 sidecar 并删除 binding。未达续写上限时只能发放一次性 continuation token，run 进入 `blocked` 并通过 `parent_run_id` 建立子 run lineage；token 必须 bounded、可过期、单次消费，预算增加必须先创建 `budget_approval` checkpoint 并由老师批准，SQLite 抢占必须依据变更行数保证并发单赢家，renderer 只能看到可继续摘要，不能拿到 request/system prompt/工具 schema；AI 对话必须提供真实继续与预算批准入口，禁止把受限续写描述成无限恢复或完整 settlement。
- R11 运行变更：retry/branch/regenerate 必须从本地私有 request snapshot 重建，不得让 renderer 传入任意系统提示或工具定义；retry 只允许失败/阻断/取消源运行，成功源使用 branch/regenerate。子 run 必须持久化 `parent_run_id`，action 使用 `(source_run_id, action, idempotency_key)` 唯一约束与主进程串行队列；重复变更只能复用已有子 run，不能重复执行写工具。UI 入口必须走 typed preload，不能把 raw request snapshot 回显给教师。
- R05 按需工具披露：`router.allowedTools` 是不可扩大的硬总许可；模型首轮只可见 `load_tools`、受 route 允许的 `ask_user/resolve_student_reference`，工具族 schema 必须由主进程审核后下一轮加载。`load_tools` 只返回 schema 与 `toolsExecuted=false`，不得执行业务工具；Python sidecar 不得把完整 catalog 直接暴露给 AgentLoop，越权工具族必须 blocked。
- 前端接线验收：后端已有能力必须在 [docs/26_FRONTEND_E2E_COVERAGE_MATRIX.md](docs/26_FRONTEND_E2E_COVERAGE_MATRIX.md) 中逐项标记 backend/frontend/e2e/live，renderer 不得继续显示“未接入”来掩盖已有入口；业务规则仍归主进程和 typed preload，不能在 renderer 复制写入或脱敏逻辑。
- 教师主闭环的 UI 必须显式呈现 loading、empty、success、failed、needs_ocr、needs_review 和 no-key 状态；Electron smoke 至少覆盖 1366×768 与 1920×1080。单独的主进程 smoke、proxy 或 deterministic 结果不得冒充前端 E2E 或真实模型验收。

### 2026-08-12 增量约束：专题讲义前端

- `TeachingBookWorkspace` 只能通过 typed preload 复用现有 book/chapter/page/block/source/health/patch 能力；直接编辑必须携带版本，协作 patch 草稿必须零正文写入，只有教师点击应用后才变更内容。

- 安全预览保持 `writesFile=false`；Markdown 导出先取得本地 data root 并写入受控 `exports/ai-artifacts`，回读真实路径、大小与 SHA-256。归档无 restore IPC 时不得伪造恢复按钮。

### 2026-08-12 增量约束：结构化结果预算

- DeepTutor AgentLoop 的模型输出预算不得低于完整 `xiazhi.reply.v2` 所需的受控上限；当前统一为 8,000 tokens。sidecar 的最终 `result` 必须保留最多 64,000 字符并与 Electron main 的最终事件上限一致，普通 trace 仍保持较小边界。禁止在 provider 与 parser 之间用 512-token 或 20,000-character 隐式切片把合法 JSON 人为截断。

### 2026-08-12 增量约束：AI 文档产物前端验收

- Markdown/PDF/DOCX 必须复用同一产物面板和既有 `exportDocumentArtifact` 链路；空正文必须在面板内显示失败并保持文件与 `document_artifacts` 零写入，成功则验证真实文件、SHA-256、SQLite 与重启 readback。
- PDF/DOCX 验收必须包含中文/Unicode；DOCX 长文样本须以实际字符长度断言，不得用“行数很多”替代超长正文证据，也不得为通过测试降低阈值。

### 2026-08-12 增量约束：学习路径前端

- 学习路径 renderer 只能按当前选择学生调用既有 `getAiMasteryPath`，切换学生时必须先清空旧路径再读取，禁止短暂显示上一名学生的数据。
- `ai_mastery_paths` 只证明教师确认的路径顺序、模式和版本，不证明掌握百分比；UI 不得从模块数量或知识点类型推导学习程度。
- 路径修改继续由小智生成草稿并进入教师确认，学习路径页面不得新增直接写入或绕过确认的 renderer 逻辑。

### 2026-08-12 增量约束：全局搜索前端

- “搜索”页面必须调用既有 `searchAll → search:all → store.search`，不得把当前学生的局部时间线筛选伪装成全局检索。

### 2026-08-12 增量约束：模型 JSON 语法修复

- 本地语法修复输入最多 64,000 字符，且必须以 `{` 开始、以 `}` 结束；截断 JSON、非对象输出或修复后契约不完整继续 fail-closed。
- 新增 parser 依赖必须锁定精确版本、接受构建与结构化回复回归，并单独说明现存依赖审计告警，不能借 bug 修复升级无关依赖。

### 2026-08-12 增量约束：学生档案生命周期

- 导出目标必须位于当前数据目录之外，取消选择目录必须零写入；校验必须分别报告缺失、被修改和清单外文件，成功也只能称为“校验通过”，不能称为已恢复或灾备完成。
- Electron E2E 可在未打包且显式 `OMNI_EDU_E2E_DIALOG_MODE=1` 时注入系统目录选择结果；生产/打包应用仍调用原生目录选择。主验收必须从 UI 点击后核对真实文件、manifest、SHA-256、篡改、取消与跨重启复验。

### 2026-08-12 增量约束：AI 对话库前端

- 当前没有对话/文件夹 restore IPC，因此设置页只能审计归档项，不得伪造恢复按钮。主 Electron 验收必须覆盖真实点击/右键/拖放、SQLite readback、级联归档、重启与双视口。
# 小智 JSON 模式恢复规则（2026-08-12）

- DeepSeek JSON 模式的空 `content` 与 `finish_reason=length` 必须在 Electron main 模型代理边界识别；仅允许一次无工具、`temperature=0`、`json_object` 的受控重试。
- 重试不得补造事实、证据或工具结果；恢复后仍必须通过完整 `xiazhi.reply.v2`、route、教育质量、可用性与写入确认校验。
- 连续空响应必须明确失败；截断 JSON 必须报告为“不完整/可能被长度上限截断”，不得统一退化成无法诊断的“没有合法 JSON”。
- sidecar 只记录可公开诊断字段：`finishReason`、`contentPresent`、`jsonRecoveryAttempted`、`jsonRecoveryReason`，不得持久化原始模型隐式推理。

### 2026-08-12 增量约束：本地复盘报告前端

- 复盘报告 renderer 只能调用既有 `generateReview`、`updateReport` 和 `listReports` typed preload；不得在 renderer 新建文件、直连 SQLite 或维护第二份持久化真源。

### 2026-08-12 增量约束：小智质量评审前端

- 设置页质量评审只能复用既有 typed preload、main IPC 与 SQLite；renderer 不重算 summary、score delta 或 Grader 结论。
- 单条表单和 CSV/TSV 必须先完整校验；预检失败保持零写入。逐行 IPC 导入不具备事务原子性，运行中失败必须明确提示按 `sampleId` 核对，不能宣称全部回滚。
- 模型评审必须展示真实 `graderMode`；deterministic proxy 不得冒充真实 `llm_judge`。失败样本“回放到 AI”只预填当前输入框，不自动发起模型调用。
- 当前 AI 输入使用稳定的 `ai-prompt-input` 验收标识，不能继续依赖已隐藏的旧输入框选择器。

### 2026-08-12 增量约束：DeepTutor 控制台故障定位

- 当前 AI 中控台用户路径调用 `runDeepTutorConsole`；旧 `runDeepSeek` smoke 不能证明当前控制台链路可用。

- 同步控制台遇到 `waiting_input` 时必须有明确的用户输入交接或可解释失败；不能让调用一直等待到 wall-timeout 后再返回空结果。

### 2026-08-12 增量约束：小智 Agent Harness v1

- AI 中控台必须先由 route/subIntent 选择 capability；映射单一事实来源是 `agent-harness-profile.ts`，HostToolProxy 不得维护另一份漂移表。
- 中控台请求必须声明 `executionProfile=omni_console`，保留 capability 权限语义并统一进入已接通 Omni 工具、结构化回复和质量门禁的 DeepTutor AgentLoop；不得把该 profile 冒充原生高级 Capability 的完整执行管线。
- 同一 turn 的学生引用解析状态必须跨 HostTool 调用保留；已经成功解析学生后，后续工具不得因参数中没有重复携带 studentId 而退回 `ask_user`。
- `waiting_input` 是可恢复中间状态：renderer 提交答案前 Console IPC 继续等待，提交后必须收敛到 succeeded/failed/blocked/cancelled，不能提前返回空回复。
- Sidecar 仓库根目录必须通过有界探测确认 Python 模块存在；异常 stderr 只能保留脱敏、bounded 尾部用于可行动错误，不得发给模型或保存密钥。

- 详细架构、映射和验收命令以 `docs/27_XIAOZHI_AGENT_HARNESS_ENGINEERING.md` 为准。

### 2026-08-30 增量约束：小智双路径执行

- AI 中控台先执行保守的 `direct | structured` 判定。寒暄、致谢、能力说明和无本地上下文的独立通识问答可走 direct；任何学生引用、学习记录、档案、附件、知识库、题库、文档产出、写入、风险判断或歧义必须走 structured。
- direct 必须在 `startDeepTutorTurn` 前返回，不得加载学生上下文、工具 schema、DeepTutor AgentLoop、`xiazhi.reply.v2` repair 或 grader；structured 继续保留 capability、工具权限、证据、结构化校验、质量门禁和教师确认链。
- UI 不展示隐藏推理链。direct 只显示答案和中性等待态；structured 只展示真实发生的路由、上下文、工具、确认和结果事件。新请求必须清空上一轮 DeepTutor 事件。
- `AiConsoleRunResult.executionMode`、`schemaApplicable`、`graderApplicable` 必须同步写入审计结果，不能把“不适用”记录成“未通过”。可用 `OMNI_EDU_AI_EXECUTION_MODE=structured` 或 `OMNI_EDU_DISABLE_DIRECT_AI=1` 回退到全 structured。
- 日常门禁为 TypeScript、轻量路由批量样例和 Enter 单次发送；真实 provider 质量与完整 Electron E2E 仍是更高层证据，不能被轻量 smoke 冒充。

- 核心产品固定为“教师个人知识库、题库与智能组卷工作台”，服务 K-12 独立教师与小微教研团队，不扩展为学校级平台、学生端、家长端或完整 LMS。
- 任一模块只有在主进程/Worker、typed preload、可操作前端、失败状态、SQLite/文件 readback、重启保持和 Electron E2E 同时成立时才可标记完成；后端 smoke 不得替代用户验收。
- OCR 默认采用 RapidOCR + ONNX Runtime，公式与复杂版面走 PaddleOCR PP-StructureV3/PP-FormulaNet；模型替换前必须通过固定教师资料评测集。
