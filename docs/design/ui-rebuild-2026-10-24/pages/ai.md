# 问小智 UI约束

状态：用户已批准布局与过程基线；逐页真实业务验收另记。

页面ID：ai；页面类型：conversation。

目的：给出教学任务，观察真实过程，获得可用结果。

默认主要行动：发送任务

## 布局与行为

- 运行说明与正文同一阅读列；过程结束先收起，再输出正文
- 工具图标根据实际操作分类；详情按需展开
- 原生推理仅详情；审批和教师问题保持可达
- 只在过程上方计时；输入区不堆任务遥测

## 输入框上方的待处理面板

- 当前对话需要老师补填简短信息、选择方案或确认操作时，必须复用 `PiComposerPendingPanel` 及对应业务内容组件。弹窗锚定在输入框正上方，采用浅色区分背景，用中文说明需要做的事。多个待办只占一个面板，切换时可见待办总数和类型。正文和右栏可提示并定位到同一待办，表单和决定按钮统一放在弹窗里。
- 面板自动出现时保留原键盘焦点。按钮或面板内 Esc 只收起展示，重新展开仍见已选项和未提交输入。输入法选字期间保留文本。长内容在面板内滚动，发送框和面板标题保持可达。
- 追问使用持续可见的中文填写标签，填写框占满正文可用宽度并显示多行。长问题和选项在正文区滚动，「发送回答」保持可见。空白回答不可提交。填写框内 Enter 换行，Ctrl+Enter 提交。输入法选字时快捷键不提交。回答沿原宿主接口校验，失败时保留已填内容。
- 会话顶部的待办提示可重新打开并定位对应事项。常见授权用中文操作名，显示原授权范围和决定按钮。
- 绑定当前会话及原 Run 的待处理事项。权限、审批、草稿持久化和恢复继续由原业务负责。完成后的记录及冷启恢复入口在原对话或工作台可读。完整试卷、长稿编辑、原件比对沿已有专业工作面。
- 会话空闲时，宿主允许恢复的历史追问在同一弹窗显示「继续回答小智的问题」。回答后沿原任务启动恢复轮次。新回复期间优先展示本轮待办，历史追问保留为只读记录。旧权限及文件确认继续经过原宿主校验。

## 必须验证

- 公开说明→真实工具→收起→正文，完整观察一轮
- 停止、失败、无公开说明、旧会话重开都可理解
- 当前待办只出现一个操作入口。核对实际窗口两种尺寸，长内容下可见的提交按钮、选择、自填、空白禁用、换行和快捷键、输入法、收起后重开、权限决定、结果历史与跨会话隔离。
- 重启后无模型自动重放。原会话的可补答追问可从顶部定位回唯一弹窗，提交后保留原任务身份。已经取消的任务不因补答重启。

共享状态：loading / empty / ready / running / partial / completed / cancelled / failed / retry。

尺寸：亮色1366×768与1920×1080；不覆盖原厂组件尺寸、圆角、颜色或交互态。
