# Omni-Edu Agent UI 重设计方案

版本：v0.2
日期：2026-07-28
状态：当前 UI 重构基准 + AI/知识库落地状态
依据：`docs/11_STRATEGIC_PRODUCT_PRD.md`、`docs/17_FRONTEND_HEROUI_PRO_DESIGN_ARCHITECTURE.md`、`docs/19_FULL_PRODUCT_DEVELOPMENT_PLAN.md`

## 1. 重设计结论

Omni-Edu Agent 的主界面不应继续呈现为“功能堆叠的开发工作台”，也不应扩成学校级 LMS 或教务 SaaS。

新的 UI 定位是：

> 老师每天通过 AI 中控台调度学生资料、个人知识库、学习证据、错题资产和阶段复盘的本地教学资产工作台。

界面必须围绕真实工作动作组织，而不是围绕开发阶段、产品线说明或未完成能力组织。

## 2. 设计方向

### 2.1 视觉锚点

采用 Swiss 工作台风格：

- 表面：`#FFFFFF` 与 `#F7F7F8`。
- 字体：Helvetica Neue / Microsoft YaHei / Arial，同一无衬线体系。
- 强调色：Yves Klein Blue `#002FA7`，只用于当前选中、主要操作和关键证据链接。
- 结构：1px 细线、明确栅格、左对齐排版。
- 信息密度：适合老师长时间录入和查阅，不做营销页、不做大面积装饰。

### 2.2 可见差异化

使用编号工作区、AI 工具调用轨迹和右侧检查器：

```text
01 一句话任务
02 可调用数据
03 证据与图谱
04 老师确认
```

老师在任何页面都应知道：

- 当前处理哪个学生。
- AI 准备调用哪些数据和工具。
- 当前处在哪个任务。
- 当前数据是否已经本地保存。
- 当前报告或 AI/OCR 输出是否需要人工确认。

## 3. 产品信息架构

完整产品 UI 分为 10 个一级工作区。前期重点是“AI 中控台”和“老师知识库”。

### 3.1 今日工作台

目标：打开软件后直接知道今天可以做什么。

模块：

- 最近学生。
- 当前学生的最近证据。
- 待处理复盘。
- AI/OCR 任务状态。
- 本地存储和备份状态。
- 快速操作：新建学生、添加记录、导入错题、生成复盘。

### 3.2 AI 中控台

目标：老师用一句话调用学生数据、学习记录、老师知识库、知识图谱和复盘/题组工具。

模块：

- 一句话任务输入框。
- 当前上下文：学生、科目、时间范围、知识库范围。
- 可调用数据：学生档案、学习记录、错题、附件、复盘、老师知识库。
- 工具调用轨迹：检索学生、检索知识库、查询图谱、生成复盘、生成题组。
- 证据引用：每个回答引用到源记录、资源片段或图谱节点。
- 老师确认：写入类动作必须人工确认。

当前骨架要求：

- 未接入模型时显示“AI 调用未接入”。
- 不伪造 AI 回答、工具返回或图谱结论。
- 可以展示真实本地数据计数和待接入工具清单。

### 3.3 老师知识库

目标：沉淀老师投入的大量知识资源，包括 PDF、Word、PPT、图片、讲义、题库、教案，并让 AI 能检索和引用。

模块：

- 资源导入。
- 解析队列。
- 文档结构预览。
- 知识资产列表。
- 知识图谱可视化。
- AI 使用记录。
- 人工校正入口。

当前骨架要求：

- 明确展示 Docling、MinerU、向量检索、知识图谱、Agent 调用的待接入状态。
- 不展示假资源、假解析结果或假图谱。
- 可以展示已有附件和本地数据目录作为真实底座。

### 3.4 学生档案

目标：沉淀长期学生资料和证据链。

模块：

- 学生搜索与筛选。
- 学生基础档案。
- 当前问题。
- 阶段目标。
- 家长关注点。
- 标签。
- 学习记录时间线。
- 附件列表。
- 历史复盘。

### 3.5 证据录入

目标：降低老师持续记录成本。

模块：

- 当前学生选择。
- 学习记录表单。
- 记录类型、科目、标题、正文、标签、发生时间。
- 附件导入入口。
- 保存后继续录入。
- 草稿状态和错误提示。

验收目标：

- 老师 3 分钟内新增一条完整记录。
- 标题为空时禁止保存。
- 保存失败时不丢失表单内容。

### 3.6 错题资产

目标：为 AI 错题产品线建立独立工作区，不把 OCR/错因分析藏进附件管理。

标准流程：

```text
导入错题图片
-> OCR 识别
-> 老师校正
-> 标记知识点
-> 标记错因
-> 召回相似题
-> 生成三元题组
-> 保存到学生档案
```

当前骨架要求：

- 明确显示 OCR、错因分析、相似题召回尚未接入。
- 可展示当前学生已有的错题记录。
- 不使用假题目、假识别结果或假 AI 任务。

### 3.7 阶段复盘

目标：生成可追溯、可编辑、可保存的复盘报告。

布局：

```text
左侧：复盘条件与源记录
中间：报告编辑器
右侧：质量检查与家长版摘要
```

质量检查：

- 是否有证据。
- 是否包含进步点。
- 是否包含薄弱点。
- 是否包含下阶段建议。
- 是否区分知识问题和习惯问题。
- 家长版是否克制。
- 是否可编辑保存。

### 3.8 资料搜索

目标：跨学生、记录、报告和附件元数据检索。

当前阶段：

- 学生搜索。
- 当前学生记录筛选。
- 关键词、类型、科目、标签、时间范围。

后续阶段：

- SQLite FTS5。
- 附件抽取文本。
- 相似记录和相似错题召回。

### 3.9 团队协作

目标：为 3-30 人小团队预留协作工作区。

模块：

- 老师账号。
- 学生分配。
- 学生交接。
- 统一标签库。
- 统一报告模板。
- 复盘审核。

当前骨架要求：

- 只展示真实数据底座状态。
- 未实现功能标记为“未接入”。
- 不伪造团队成员、审核队列或绩效数据。

### 3.10 经营看板

目标：服务小团队负责人查看教学交付质量。

模块：

- 在读学生数。
- 学习记录数。
- 复盘报告数。
- 附件资料量。
- 待续费风险。
- 老师跟进完成率。
- 高频薄弱点分布。

当前骨架要求：

- 使用已有本地聚合指标。
- 不展示假的趋势图。
- 明确经营指标聚合仍处于预留阶段。

## 4. 页面骨架

### 4.1 全局布局

```text
左侧：全局导航
中间：当前工作区
右侧：上下文检查器
```

左侧全局导航固定为：

```text
今日
AI
知识库
学生
录入
错题
复盘
搜索
团队
看板
设置
```

中间主工作区根据导航切换。

右侧检查器始终展示：

- 当前学生。
- 当前任务状态。
- AI 工具调用状态。
- 老师知识库解析状态。
- 本地数据目录。
- 附件导入状态。
- 报告质量检查。
- 未接入能力的透明说明。

### 4.2 学生档案页

```text
左：学生目录
中：学生画像 + 证据时间线
右：上下文检查器
```

学生列表只在学生相关页面内出现，不再作为全局唯一侧栏。

### 4.3 录入页

```text
左：当前学生与最近记录
中：记录表单
右：录入规则和本地保存状态
```

### 4.4 复盘页

```text
左：条件和源记录
中：报告编辑器
右：质量检查和家长摘要
```

### 4.5 AI 中控台页

```text
左：上下文选择
中：一句话任务输入 + AI 输出区
右：工具调用轨迹 + 证据引用
```

### 4.6 老师知识库页

```text
左：资源导入与资源列表
中：解析队列与文档结构
右：知识图谱可视化与 AI 使用状态
```

## 5. 内容规则

- 页面文字必须说明真实功能、真实状态或明确的未接入状态。
- 不出现“完整产品工作台”这类开发口径标题作为主操作内容。
- 不出现假 AI 输出、假团队成员、假经营趋势。
- 标准操作使用标准文案，例如“保存记录”“生成复盘”“导入附件”。
- AI/OCR 必须展示为可确认、可编辑、可失败重试的任务，不做神秘化包装。
- AI 不能直接写库，所有写入都必须先显示为待老师确认。
- 知识库不能伪造已解析资源、图谱节点或引用记录。

## 7. 验收清单

- 老师 5 秒内知道今天可以做什么。
- 老师 5 秒内能找到 AI 中控台和老师知识库。
- AI 中控台能说明当前可调用哪些真实数据。
- 老师知识库能说明资源导入、解析、图谱和 AI 调用的状态。
- 老师 3 分钟内能完成一条学习记录。
- 老师能在学生页看到当前问题、阶段目标和证据时间线。
- 附件状态清楚展示本地路径、大小、复制结果和失败原因。
- 复盘报告必须可编辑保存。
- 报告质量检查始终可见。
- 未实现功能不能伪装成已实现功能。
- AI 输出不能直接写入数据库，必须由老师确认。
- 页面不引入账号登录、排课收费、学生端、家长端或学校级管理。
- 1440x900、1280x800、390x920 下无横向溢出和文字重叠。

## 8. 当前落地状态

本轮 UI 和功能已经完成以下调整：

- AI 中控台已经接入 DeepSeek，运行按钮不再只是占位。
- 设置页支持手动保存/更新 DeepSeek API Key，界面只显示掩码。
- AI 中控台会展示当前模型、真实数据源、工具调用轨迹、知识库引用和图谱节点数量。
- 老师知识库页已经接入本地资源导入、资源列表、解析队列、文档切片预览、知识图谱节点/边统计。
- TXT / Markdown 资源会立即生成可检索切片；PDF、Word、PPT、Excel、图片进入解析队列。
- 未完成的 Docling、MinerU、OCR、向量检索、Sigma.js 大图谱仍在 UI 中透明显示为待接入，不伪造成已完成。
