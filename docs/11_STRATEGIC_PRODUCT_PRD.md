# Omni-Edu Agent 战略产品 PRD

版本：v0.1  
日期：2026-07-28  
目标读者：产品、研发、设计、测试、后续商业化负责人  
产品阶段：从个人老师桌面 MVP 到中小教辅团队 AI 教学交付系统

## 1. 战略结论

Omni-Edu Agent 不应定位为又一个教务 SaaS，也不应定位为学生端搜题工具。

产品应定位为：

> 面向个人老师与中小教辅团队的本地优先 AI 学生档案与个性化教学交付系统。

核心战略判断：

1. 国内教培 SaaS 已经在招生、排课、收费、课消、家校通知上非常成熟，正面竞争难度高。
2. 作业帮、小猿搜题、讯飞错题本等工具已经证明“错题资产化、相似题推荐、学习报告”有强需求，但它们偏学生端或大机构方案。
3. 个人老师和 3-30 人小团队仍缺一个低门槛工具，把学生长期资料、课堂记录、错题、附件、家长沟通和阶段复盘沉淀成可复用资产。
4. 产品初期必须先解决“老师愿不愿意持续记录”和“家长能不能看到可信证据”，然后再扩展到团队协作、AI 错题资产和机构经营。

一句话产品主张：

> 把老师散落的学生资料变成可追溯、可复盘、可续费沟通的本地教学资产。

## 2. 产品主打核心优势

### 2.1 本地优先，适合真实教辅场景

中小教辅团队和个人老师常见资料包括试卷照片、PDF、Word、作业截图、课堂笔记、家长聊天记录摘要等。单个学生资料可能达到数 GB，全部云端化成本高、隐私压力大、迁移阻力强。

产品优势：

- SQLite 保存结构化数据。
- 本地文件系统保存大附件。
- 每个学生独立资料目录。
- 云端 AI 只接收脱敏摘要，不接收原始附件。
- 后续可扩展局域网共享目录或私有云备份。

### 2.2 学生长期档案，而不是一次性课后记录

许多工具只记录排课、考勤、收费或单次课程点评。Omni-Edu Agent 的核心是以学生为中心沉淀长期证据链。

产品优势：

- 学生基础档案。
- 学习目标。
- 当前问题。
- 家长关注点。
- 学习记录时间线。
- 附件资料库。
- 错题与知识点标签。
- 阶段复盘历史。

### 2.3 阶段复盘驱动续费与家长信任

中小教辅团队的商业关键不是“功能多”，而是家长是否相信服务有效、是否愿意续费。

产品优势：

- 按时间范围生成阶段复盘。
- 自动汇总高频薄弱点、高频错因、学习习惯、进步点。
- 输出教师版和家长沟通版。
- 每个结论可回溯到学习记录、标签或附件。
- 老师可编辑确认，避免 AI 一键定稿造成风险。

### 2.4 AI 可控，不替代老师

AI 的角色不是直接教学，也不是直接判定学生能力，而是帮助老师完成低价值、高频、耗时的整理工作。

产品优势：

- 先规则模板生成，再接大模型润色。
- 输出必须结构化。
- 大模型输入必须脱敏。
- 报告必须可编辑。
- 错因、建议、家长话术必须保留证据引用。

### 2.5 从个人工具自然升级到小团队系统

产品第一阶段服务个人老师，但架构和数据模型必须预留小团队协作。

产品优势：

- 单机可用，降低启动门槛。
- 后续增加老师账号、学生分配、报告审核、统一标签库。
- 不一开始做重权限和复杂教务，避免 MVP 失焦。

## 3. 市场与竞品启发

### 3.1 国外轻量教培工具

TutorBird 的启发：

- 适合个人老师和小团队。
- 重视学生管理、家庭联系人、课程记录、资源分享、家长沟通。
- 低门槛比大而全更重要。

Teachworks 的启发：

- 成长型机构需要可扩展 add-ons。
- 课程笔记、结果追踪、在线课堂和第三方集成有价值。
- 多老师、多地点、多时区属于后续扩展，而不是 MVP 核心。

TutorCruncher 的启发：

- 机构老板需要排课、账单、工资、提醒和经营看板。
- 经营后台是商业化高级版能力，不应压到第一版。

### 3.2 国内教培 SaaS

校宝、校管家、小禾帮等产品的启发：

- 国内机构强需求集中在招生、续费、课消、家校服务和数据分析。
- 家长沟通、成长档案、课堂点评能直接影响续费。
- 教务系统已经很成熟，Omni-Edu Agent 不应第一阶段硬拼排课收费。

### 3.3 错题与个性化学习工具

作业帮、小猿搜题、讯飞错题本的启发：

- 拍照识题、错题归类、相似题推荐、打印练习有明确需求。
- 学生版和教师版报告应分离。
- 错题资产如果和老师长期档案结合，会比单点搜题工具更适合小教辅团队。

### 3.4 AI 教师工具

MagicSchool 等 AI 教师工具的启发：

- AI 最容易落地在教案、反馈、邮件、报告、评语等高频文本任务。
- AI 必须嵌入教师工作流，而不是另起一个聊天入口。

## 4. 目标用户

### 4.1 第一目标用户：个人老师

画像：

- K-12 学科老师。
- 课后辅导老师。
- 一对一或小班老师。
- 维护 20-100 个学生。
- 用微信、文件夹、Excel、纸质笔记管理资料。

核心痛点：

- 学生资料散。
- 每次家长沟通都要重新翻材料。
- 复盘报告耗时。
- 错题和附件难长期管理。
- 教学经验无法结构化沉淀。

### 4.2 第二目标用户：中小教辅团队

画像：

- 3-30 人老师团队。
- 本地小机构、工作室、小微教研团队。
- 有续费压力，但没有成熟数字化能力。
- 不想上复杂 SaaS，或觉得传统教务系统不解决教学交付问题。

核心痛点：

- 不同老师服务质量不一致。
- 学生转交困难。
- 家长反馈依赖个人表达能力。
- 续费时缺证据。
- 老师离职带走资料。

### 4.3 暂不服务用户

- 公立学校全校级管理。
- 大型连锁机构总部。
- 家长端独立 App 用户。
- 学生端自主学习用户。
- 完整 LMS 平台用户。

## 5. 产品线规划

### 5.1 产品线 A：个人老师桌面版

定位：

> 单个老师的本地学生档案与复盘工具。

核心功能：

- 学生档案。
- 学习记录。
- 附件归档。
- 时间线。
- 本地搜索。
- 阶段复盘草稿。
- 家长沟通版摘要。

技术形态：

- Electron + Vite + React + TypeScript。
- SQLite。
- 本地文件目录。
- 后续接 Python OCR 和本地检索。

商业形态：

- 免费试用。
- 个人专业版一次性买断或低价订阅。
- AI 能力可按量或包月。

### 5.2 产品线 B：小团队协作版

定位：

> 3-30 人教辅团队的教学交付标准化系统。

核心功能：

- 老师账号。
- 学生分配。
- 学生转交。
- 统一标签库。
- 统一复盘模板。
- 复盘审核。
- 家长沟通记录。
- 待续费提醒。
- 团队工作量统计。

技术形态：

- 单机 + 局域网共享目录，或轻量云同步。
- 管理员与老师角色。
- 后续支持私有化部署。

商业形态：

- 按老师席位收费。
- 按学生档案容量或 AI 用量收费。

### 5.3 产品线 C：AI 错题资产版

定位：

> 把学生错题、题库和复习建议沉淀为机构核心教学资产。

核心功能：

- 错题图片导入。
- OCR 识别。
- 手动校正。
- 知识点标签。
- 错因标签。
- 相似题召回。
- 三元题组输出：原题、相似题、巩固题。
- 可打印练习 PDF。

技术形态：

- Python OCR pipeline。
- SQLite + FTS。
- 后续本地向量库。
- 脱敏后调用大模型分析错因。

商业形态：

- AI 增值包。
- 按识别页数、题目数或报告数计费。

### 5.4 产品线 D：机构经营增强版

定位：

> 给小机构老板看的服务交付与经营质量看板。

核心功能：

- 在读学生数。
- 待续费学生。
- 高风险学生。
- 本月学习记录数。
- 本月复盘报告数。
- 老师跟进完成率。
- 家长沟通完成率。
- 高频薄弱点分布。
- 科目需求分布。

注意：

排课、收费、课消是后置能力。第一阶段只保留接口和数据结构预留，不进入 MVP。

## 6. MVP 范围

### 6.1 MVP 目标

在 2-4 周内跑通个人老师最小闭环：

```text
创建学生 -> 添加学习记录 -> 上传附件 -> 本地保存 -> 时间线查看 -> 生成阶段复盘 -> 老师编辑保存
```

### 6.2 MVP 必须做

#### P0-1 学生档案

功能：

- 新建学生。
- 编辑学生。
- 归档学生。
- 学生列表。
- 按姓名、年级、科目、标签搜索。

字段：

- 显示名。
- 真实姓名，可选。
- 年级。
- 学校，可选。
- 关注科目。
- 学习目标。
- 当前问题。
- 家长关注点。
- 老师备注。
- 标签。
- 状态。

验收：

- 能创建不少于 30 个学生。
- 关闭应用后重新打开，学生数据仍存在。
- 搜索结果在 100 个学生规模下即时响应。

#### P0-2 学习记录

功能：

- 给学生添加学习记录。
- 支持课堂、作业、试卷、错题、沟通、阶段总结。
- 支持科目、标题、正文、标签。
- 支持发生时间。
- 支持编辑记录。
- 支持按时间倒序展示。

验收：

- 同一学生可添加多条记录。
- 时间线顺序正确。
- 老师能在 3 分钟内新增一条完整记录。

#### P0-3 附件管理

功能：

- 选择本地文件作为附件。
- 默认复制到学生资料目录。
- 保存文件名、路径、类型、大小、hash。
- 支持打开附件所在目录。
- 大文件不写入数据库。

验收：

- 一条记录可挂多个附件。
- 50MB 以上文件导入时不会造成 UI 卡死。
- 数据库只保存路径和元数据。

#### P0-4 学生时间线

功能：

- 按时间展示所有学习记录。
- 展示记录类型、科目、标题、摘要、标签、附件。
- 支持类型、科目、标签筛选。

验收：

- 1000 条记录下滚动和筛选体验可接受。
- 能从时间线打开附件所在位置。

#### P0-5 阶段复盘草稿

功能：

- 选择学生。
- 选择时间范围。
- 选择科目。
- 聚合对应记录。
- 按标签和记录类型统计。
- 模板生成 Markdown 草稿。
- 生成教师版和家长沟通版。
- 支持编辑并保存。

验收：

- 能基于真实记录生成报告。
- 报告包含整体表现、进步点、高频薄弱点、典型错因、学习习惯、下阶段建议、家长沟通版摘要。
- 报告保存后可在学生详情中查看。

### 6.3 MVP 暂不做

- 不做账号登录。
- 不做云同步。
- 不做团队权限。
- 不做完整排课。
- 不做收费课消。
- 不做家长端。
- 不做学生端。
- 不做复杂 OCR 自动识别。
- 不做自动判分。
- 不做完整组卷。
- 不做复杂 Word/PDF 图文解析。

## 7. 核心用户流程

### 7.1 新建学生流程

```text
点击新建学生
-> 填写基础信息
-> 填写学习目标和当前问题
-> 添加标签
-> 创建本地学生目录
-> 写入 SQLite
-> 进入学生详情页
```

异常处理：

- 学生名为空：禁止保存。
- 本地目录创建失败：提示原因并允许重试。
- SQLite 写入失败：保留表单内容，不丢失输入。

### 7.2 添加学习记录流程

```text
选择学生
-> 点击添加记录
-> 选择记录类型和科目
-> 输入标题和正文
-> 添加标签
-> 可选添加附件
-> 保存记录
-> 时间线刷新
```

异常处理：

- 标题为空：禁止保存。
- 附件复制失败：记录仍可保存，但附件标记失败状态。
- 大文件复制中：显示进度，不阻塞主界面。

### 7.3 生成阶段复盘流程

```text
选择学生
-> 选择时间范围
-> 选择科目
-> 查询学习记录
-> 聚合标签、类型、附件摘要
-> 生成结构化摘要
-> 生成 Markdown 草稿
-> 老师编辑
-> 保存报告
```

异常处理：

- 时间范围内无记录：提示先添加学习记录。
- 报告生成失败：保留聚合数据，允许重试。
- 保存失败：报告内容保留在编辑器中。

## 8. 页面规划

### 8.1 主工作台

布局：

- 左侧：学生列表、搜索、新建学生。

## 10. 技术方案

### 10.1 桌面端

技术栈：

- Electron
- Vite
- React
- TypeScript
- HeroUI v3
- HeroUI Pro
- Tailwind CSS v4
- SQLite

进程边界：

```text
React Renderer
-> preload 安全暴露 API
-> Electron Main
-> SQLite / 文件系统 / Python CLI / AI API
```

约束：

- Renderer 不直接访问文件系统。
- Renderer 不直接执行命令。
- 所有本地文件、数据库、AI 调用通过 preload 暴露的安全 API。
- 前端工作台、侧边栏、时间线、附件导入、报告编辑、看板和 AI 任务展示优先复用 HeroUI Pro。
- 业务页面必须经过项目内 `shared/ui` 封装使用 HeroUI Pro，避免后续升级困难。

### 10.2 本地存储

默认目录：

```text
C:\Users\<User>\AppData\Roaming\OmniEduAgent\
```

目录结构：

```text
OmniEduData/
  app.db
  config/
    settings.json
  students/
    student_001/
      profile.json
      records/
      attachments/
      reports/
  indexes/
  cache/
  backups/
```

### 10.3 AI 接入

MVP：

- 不依赖大模型。
- 使用规则和模板生成报告。

后续：

- DeepSeek 或其他模型。
- 输入脱敏摘要。
- 输出 Markdown 或 JSON Schema。
- 老师编辑确认。

AI 安全约束：

- 不上传原始附件。
- 不上传真实姓名和学校。
- 不上传完整聊天记录。
- 日志不记录学生隐私全文。

## 11. 版本路线

### V0.1 桌面原型

## 14. 风险与控制

### 14.1 需求跑偏风险

风险：

- 产品变成重型教务 SaaS。

控制：

- MVP 不做排课、收费、课消。
- 先做学生档案和复盘闭环。

### 14.2 AI 幻觉风险

风险：

- AI 生成无证据结论。

控制：

- 报告必须引用源记录。
- 老师必须编辑确认。
- AI 输出结构化校验。

### 14.3 隐私风险

风险：

- 上传学生敏感信息。

控制：

- 本地优先。
- 脱敏后上云。
- 日志不记录隐私全文。

### 14.4 老师录入负担风险

风险：

- 老师嫌麻烦，不持续使用。

控制：

- 3 分钟记录目标。
- 标签复用。
- 常用模板。
- 后续语音转文字和 OCR 辅助。

### 14.5 文件管理风险

风险：

- 附件丢失、路径失效、误删。

控制：

- 默认复制到学生目录。
- 保存 hash。
- 删除先归档。
- 支持导出数据目录。

## 16. 对抗性审查清单

每个版本发布前必须检查：

- 是否仍围绕学生档案、记录、附件、复盘闭环。
- 是否引入了不必要的学校级平台能力。
- 是否有任何原始附件被自动上传。
- 是否有任何 AI 输出不可编辑。
- 是否有任何报告结论无法追溯证据。
- 是否能在无网络状态下完成核心流程。
- 是否能解释每个功能如何帮助老师节省时间或提升家长信任。

## 18. 最终产品原则

1. 先做个人老师高频刚需，再做团队协作。
2. 先沉淀学生资料，再谈 AI 个性化。
3. 先生成可编辑复盘，再做自动错题分析。
4. 先本地可信，再逐步云端协作。
5. 先服务教学交付，再扩展经营管理。

最终目标：

> 成为个人老师和中小教辅团队的 AI 教学资产操作系统。
