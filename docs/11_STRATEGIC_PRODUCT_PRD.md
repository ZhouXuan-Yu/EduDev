# Omni-Edu Agent 最终产品与模块方案

版本：v1.0  
确认日期：2026-09-16  
状态：产品与模块唯一权威基线

## 1. 产品定义

Omni-Edu Agent 是面向 K-12 独立教师和小微教研团队的本地优先桌面工作台：把教师长期积累的 30–40GB 教材、教案、讲义、试题、答案与解析转化为可检索、可追溯、可组卷的个人教学资产；同时把学生错题照片转化为可修正的错题记录和针对性练习。

它解决三个直接问题：

1. 资料多而散，教师无法稳定检索、复用和追溯原文。
2. 组卷、改编题和编写解析重复耗时，来源和质量难控制。
3. 学生错题停留在照片或聊天记录，无法形成下一轮针对性练习。

产品价值不是“AI 能聊天”，而是教师能从自己的资料和真实错题快速得到可编辑、可验证、可导出的教学产物。

## 2. 用户与非目标用户

第一用户：拥有大量本地资料、经常备课和组卷的独立教师。  
第二用户：共享少量资料、模板和审题流程的小微教研团队。

本产品不扩展为学校级教务系统、学生自助搜题端、家长端、完整 LMS、排课收费系统或机构经营 SaaS。多人协作只有在单机闭环稳定后，围绕共享资料、审题和版本协作单独设计。

## 3. 两条核心生产闭环

### 3.1 资料到试卷

```text
批量导入资料
-> 后台解析、去重和索引
-> 教师校正元数据/题目
-> 创建组卷蓝图
-> 题库召回 + 受控改编/生成
-> 教师逐题审核与调整
-> 导出试卷、答题纸和解析
-> 保存版本、来源和使用记录
```

组卷蓝图至少包含学段、年级、学科、教材版本、范围、知识点、题型、题量、难度、分值、用时和来源偏好。组卷不能只是一次性提示词；必须允许锁题、换题、拖拽排序、修改分值、编辑题干/答案/解析、查重和重新计算总分。

### 3.2 错题到针对性练习

```text
导入学生错题照片
-> 本地 OCR/版面分析
-> 教师校正题干、答案和区域
-> 脱敏
-> 错因与知识点建议
-> 本地相似题召回或受控改编/生成
-> 教师确认
-> 导出针对性练习与解析
-> 回写来源、版本和后续表现
```

没有 OCR 文本时状态必须是 `needs_ocr`；教师修正后必须重新生成脱敏文本。原始图片默认不上传云端。

## 4. 导航与工作台

正式一级导航围绕教师任务组织：

1. 今日：导入、解析、待修正、待审核、导出失败和最近产物。
2. 知识库：文件、解析状态、元数据、分块、索引、引用与原文定位。
3. 题库：题目、答案、解析、来源、版本、标签、查重和编辑。
4. 智能组卷：蓝图、候选题、试卷编辑、校验、版本和导出。
5. 错题训练：照片、OCR 校正、错因、知识点、针对性题组和历史。
6. 学生：最小必要档案、错题和训练记录；不承担教务管理。
7. 产物：试卷、解析、讲义、报告和导出状态。
8. 设置：存储、模型、隐私、备份、诊断和质量评审。

小智是全局助手和任务入口，可以带上下文进入上述工作台，但不能取代可视化编辑、确认和错误恢复界面。知识图谱、记忆治理、研究和可视化属于内部或高级能力，不得占据默认主导航，除非有真实教师任务收益证据。

## 5. 模块开发方案

### M01 本地资料库

职责：30–40GB 文件的目录导入、增量扫描、指纹去重、状态跟踪、原文定位和生命周期管理。

实现注意：大文件留在受管目录；SQLite 只存元数据、关系和任务状态。导入支持取消、断点、失败重试、移动/缺失检测和重复文件提示。禁止把整份文件或大二进制写入数据库。

### M02 文档解析

职责：将 PDF、DOCX、PPTX、Markdown、图片等转换为结构化段落、表格、图片引用和页码坐标。

成熟方案：Docling 作为通用本地解析主线；格式原生库作为降级路径。所有解析产物带 parser/model/version/fingerprint，升级解析器后可按来源局部重建。

### M03 OCR 与公式识别

职责：错题图片、扫描页和题目区域识别，并保留置信度、区域和教师修正。

成熟方案：普通中文印刷体默认 RapidOCR + ONNX Runtime，适合桌面离线、体积和部署；复杂版面/表格使用 PaddleOCR PP-StructureV3；公式按需使用 PP-FormulaNet。先做图像方向、裁切、去噪和区域检测，再识别；低置信度必须进入人工复核，不能自动写成正确题目。

### M04 索引与检索

职责：关键词、语义和元数据过滤的混合检索，返回可定位来源。

成熟方案：SQLite FTS5 为稳定关键词底座，LanceDB 为本地向量派生索引，reranker 仅在效果评测证明有收益时加入。向量库损坏或模型缺失时降级为 FTS5；任何命中必须能回到 source/page/chunk。

### M05 题库

职责：从资料抽题、人工录题、版本管理、重复检测、编辑和历史使用。

每题必须保存学段、年级、学科、知识点、题型、难度、题干、选项、答案、解析、来源、证据定位和版本。来源限定为 `library_original`、`library_adapted`、`ai_generated`、`teacher_created`，不得混淆。

### M06 智能组卷

职责：把蓝图转换为候选题集合，在约束下补齐并输出可编辑试卷。

先从本地题库召回，再在教师允许时改编或生成。必须执行题量、总分、题型、知识点覆盖、难度分布、重复度、答案完整性和解析完整性校验。AI 只生成候选和解释，最终入卷由教师确认。

### M07 错题资产

职责：组织学生错题图片、OCR 版本、教师修正、脱敏文本、错因和知识点证据。

错因是可修改建议，不是永久学生标签；学生判断区分事实、推断和未知。图片、学生姓名、联系方式和本地路径不进入云端上下文。

### M08 针对性练习

职责：根据错题生成原题复现、同类巩固、迁移提升等题组，并追踪来源和教师修改。

优先本地相似题；不足时允许改编/生成并明确标识。正式题组只在确认后落库，修改已确认题组必须形成新草稿/版本。

### M09 小智 Agent

职责：识别任务、选择最小上下文、调用受控工具、解释证据、发起确认和交付产物。

实现基线见 `22_XIAOZHI_EDU_AI_HARNESS_PLAN.md`。对话不是业务真源，不能绕过工作台和确认队列。

### M10 产物与导出

职责：生成和管理 Markdown、PDF、DOCX、试卷、答题纸与解析。

成功必须由主进程真实写文件并保存路径、大小、SHA-256、状态和错误；预览成功不等于导出成功。模板、页眉页脚、分页和公式排版必须可独立测试。

### M11 学生与教学记录

职责：提供错题训练所需的最小学生上下文、训练历史和复盘证据。

不建立复杂教务、排课、收费和家长运营。任何长期画像都可审查、可编辑、可禁用和有证据来源。

### M12 安全、备份与诊断

职责：本地数据治理、密钥、脱敏、审计、备份校验、迁移、崩溃恢复和运行诊断。

备份必须有 manifest 和 hash 校验；日志不得含密钥、原始学生材料、完整 prompt 或隐藏推理。恢复能力要以演练证明，不以“已复制文件”证明。

## 6. 商业落地与护城河

可生产价值来自四类积累：

- 教师私有资料经过修正后的结构化题库和来源链。
- 教师对 OCR、标签、题目、解析和组卷结果的高质量修订数据。
- 真实使用形成的组卷模板、选题偏好、版本和效果反馈。
- 本地优先、可离线、可迁移、可审计带来的信任和替换成本。

模型本身不是护城河。商业化前必须证明：首批 30–40GB 导入可恢复；典型检索和组卷时延可接受；教师能在一个工作日内独立完成两条闭环；数据可备份恢复；升级不破坏老库；真实教师愿意持续使用并为节省时间或题库资产付费。

## 7. 完成定义

任何模块只有在以下链路完整时才算完成：

```text
真实数据输入
-> main/Worker 处理
-> typed preload
-> React 可操作界面
-> 明确 loading/empty/error/partial/success
-> SQLite/文件 readback
-> 重启后仍成立
-> Electron E2E
```

后端函数、数据库表、mock、构建通过或截图都不能单独证明完成。当前实现证据统一记录在 `26_FRONTEND_E2E_COVERAGE_MATRIX.md`。

## 8. 需求决策规则

新功能必须回答：是否直接缩短资料到试卷或错题到练习的时间；是否增强来源、质量、教师控制或可恢复性；是否增加不必要的平台复杂度。不能回答前两项且明显增加第三项的功能，不进入默认产品。
