# 小智 UI 设计交接决策记录

更新日期：2026-11-24

本记录用于后续正式开发交接。当前阶段继续讨论产品界面与操作体验；以下区分用户已确认的约束和仍在讨论的页面方案。

## 一、已确认的组件与视觉要求

### UI-C01 统一复用 HeroUI Pro 与项目现有 HeroUI 组件

下拉选择、折叠区、菜单、弹层、开关、提示、按钮、页签、面包屑与分页等小组件，优先使用项目现有 HeroUI 体系及可用的 HeroUI Pro 成品实现。正式实施前核对项目版本、锁文件和实际可用源码，不因组件替换顺带升级框架，也不引入第二套视觉组件体系。

HeroUI 基础组件与 Pro 组件可以共同组成统一界面；交接时记录实际使用的组件和版本，不将基础组件冒称为 Pro。

### UI-C02 替换当前粗黑箭头和未经设计的默认指示符

用户明确不接受当前示意中粗黑、突兀的箭头。正式界面不得直接保留浏览器原生 select、summary 等控件暴露的默认黑三角，也不用文本字符拼接代替图标。

展开、收起、下拉、进入和返回使用所选组件配套的指示符或项目统一图标。用完整组件承载操作，保留必要的可发现性。

### UI-C03 图标与交互状态遵循同一规范

同类图标使用统一的尺寸、描边、对齐、颜色和状态规则。颜色遵循项目主题与控件层级，不逐页硬编码纯黑。当前项、悬停项、键盘焦点、展开与禁用状态应能辨认，选中状态不能与悬停状态完全相同。

保持克制的灰白基础与蓝色重点。组件质感依靠清楚的层级、间距、状态和一致性，不增加无意义的装饰或动效。

### UI-C04 按项目既有获取路径复用组件

正式开发时优先使用项目已有集成和可用的 HeroUI Pro 工具。需要源码回退时，核对用户开发机的既有路径：

`D:\WorkProject\HeroUIPro\herouipro-v3\src`

按匹配组件一并处理样式、主题、工具函数和依赖。应用层负责页面编排，组件层负责控件视觉；避免用全局选择器覆盖组件内部所有状态。

该路径来自项目既有约定，正式执行 AI 需要在用户开发机核验；本记录不代表已在当前环境安装或验证这些本地文件。

### UI-C05 视觉替换保留完整操作能力

保留字段标签、可访问名称、键盘操作、焦点指示和展开状态等语义。按对应控件规范检查鼠标与键盘操作，以及弹层关闭后的焦点返回。

验收包含默认、悬停、选中、展开、禁用、错误和窄窗口状态。不能只验收一张静态图，也不能通过删除指示符或去掉必要标签解决外观问题。

### UI-C06 流程示意不作为正式视觉定稿

上一轮交互示意用于讨论设置分类、保存和返回路径，其中原生控件及默认箭头没有获得用户视觉认可。

正式视觉样板需使用实际 HeroUI／HeroUI Pro 组件建立，并在真实应用中验收。不能将简化 HTML 示意直接复制成正式页面后宣称达到最终设计要求。

## 二、已确认的协作与实施边界

### UI-S01 等待正式开发交接

当前继续整理页面设计和使用体验，不启动生产 UI 改造。正式交接时把本记录纳入执行任务、组件清单和验收标准。

### UI-S02 配置改造由另一 AI 负责

小智配置相关改造已有另一个 AI 承担。本 UI 专项负责页面定位、信息层级、组件呈现、教师文案、操作入口、反馈与返回关系。

涉及配置页时，以对方交付的实际能力、保存方式、作用范围和状态为依据。通过接口与状态清单衔接，不重复改写配置逻辑、权限含义、模型接入、记忆机制或持久化契约。

### UI-S03 延续已确定的产品方向

首页继续以问小智的 Agent 工作台为中心。教师在对话里发起、补充和修改要求，在功能页面中查看和精修成果；现有输入框及其整体交互保护要求继续适用。

页面应明确当前位置、用途、当前对象和下一步。日常设置使用教师能够理解的用途与结果表达，必要的专业诊断按需进入。

## 三、下一部分讨论草案

本节是建议，尚未作为用户已确认的页面决策冻结。

### 三个入口的职责

| 入口 | 建议主要职责 | 第一眼应看到什么 |
| --- | --- | --- |
| 问小智 | 交代任务、继续对话、修改要求 | 当前对话、进展摘要和相关成果 |
| 我的任务 | 查看进度、找到待处理事项、继续已有任务 | 任务名称、真实状态、下一步操作 |
| 教学工作台 | 查找、打开、整理和精修教学内容 | 已有成果与明确的分类、新建入口 |

同一任务在不同入口中保留相同名称、状态与来源关系；任务详情与成果保持同一份事实来源。

### 核心往返路径

教师在问小智中提出“生成试卷和配套 PPT”，随后查看进展、打开实际成果、修改具体题目或课件内容，再返回原对话继续调整。

页面切换应保留当前任务、成果版本、选择、滚动和未保存输入。主操作必须对应已实现的能力：有可打开成果时显示查看成果，实际只能返回对话时显示回到对话继续。

下一轮重点讨论教学工作台首屏与成果入口的组织，避免继续扩大设置配置讨论范围。
