# 03 页面与交互规范

本文件细化已确认方向；执行 AI 可完成现有页面内整理，不重新设计全局导航和业务状态。尺寸、字体、variant 优先沿现有已批准 token 和官方控件默认值。

## 所有页面共用的四个问题

每个页面让老师看到：我在哪里、正在处理什么、当前是什么状态、下一步怎么做。上方使用明确页名；有对象时显示对象名称；复杂上下层有返回入口。不要在同一屏反复显示同一个大标题，也不强行给简单页堆面包屑。

页面级主要操作保持单一视觉重点。独立对象可有自己的操作，不能把“查看、刷新、诊断、保存、返回”全部画成同等强调。只读页面的主要行动可以是选择对象 / 查看，不新增无意义“保存”按钮。

当前导航与 hover 不同；数据为空与加载失败不同；禁用操作说明真实原因，能采取补救时给具体入口。整页不要靠一串说明段落承担信息架构。

## 问小智及等待事项

- 延续输入优先、真实公开过程和成果模式。不要给首页堆多层大卡片；不展示内部私有推理或虚构工具步骤。
- 保护原输入框、附件、工具栏、配置弹层、IME、Shift+Enter、会话草稿、消息队列的追加 / 撤回行为。
- 待老师选择 / 补填 / 确认复用 PiComposerPendingPanel，位于输入框上方；一会话一个面板，可切事项和收起恢复，保持已填数据。
- 面板说明这次需要老师做什么；确认与审批仍走原宿主，不重复弹出另一套确认卡，不自动把普通请求升级为授权。
- 进入等待不抢输入焦点；长文、整卷和专门预览从面板进入已有工作面。
- 用户上翻或选字时不强制追底；右栏由用户操作打开，显示真实关联对象。

## 我的任务 / 教学任务

当前两个入口职责遵循 page-contracts.ts；本轮解决定位与展示重复，不迁移所有任务和成果的归属。

每条记录的主区域依次呈现：简明任务名、真实状态、必要约束摘要、可执行下一步。时间、完整原指令、来源和诊断放在详情。标题最长两行，完整要求始终可查看；“不含二模”等会改变结果的约束不能被只剩省略号的标题吞掉。

主动作从真实状态推导：需要老师确认则进入对应处理面板 / 原工作面；有成果则查看成果；只能回原会话则写“回到对话继续”；无合法剩余步骤时不能显示“继续执行”。空任务列表说明可从问小智发起，过滤无结果则允许清除过滤。

## 设置

沿日常 / 高级分层，保留实际必要入口；不强行套用尚未确认的六个分类。

- 一个设置分组围绕教师用途，例如教学偏好、显示和操作、文件保存；字段行集中呈现标签、当前值、控件和必要说明。
- 教学偏好可以表述为“常教学科 / 年级 / 常用教材”等，但必须由真实范围判断。不能把 profile、relevant、off 合成一个意思含混开关。
- 区分应用通用设置、教师长期偏好、当前对话设置、当前任务一次性确认。在只呈现当前对话内容时明确显示会话名；无当前会话时不能偷偷选最近一条当作全局设置。
- 控件修改 / 保存 / 保存失败 / 生效时点使用原契约。显式保存的区域提供就近保存与脏状态；即时生效的设置不增加假保存按钮。失败时保留输入，允许重试。
- 离开有未保存改动的区域采用既有保留 / 确认策略。关闭设置不能误停止对话任务或丢失聊天草稿。
- 工具注册、服务地址、运行环境、错误码、acquisition 等专业诊断按需进入；常用界面用中文说明当前影响与可做的事。错误详情仍可复制和排查。
- 已存在的设置搜索应定位到具体项目并展示选中关系；不为了增加复杂度另做全局搜索引擎。
- “请求批准 / 接受编辑 / 替我批准 / 完全访问”等权限概念，须在实际操作前保留准确的差异说明；视觉简化不得扩大授权。

## 资料库与教学文件

列表以名称、类型 / 可用状态、必要时间或来源和操作组成。导入、解析、索引、题目可用是不同状态，不能用单一“完成”遮盖失败。

详情右栏标题显示对象，来源 / 原页 / 题目 / 笔记按已有能力进入。列表到详情返回保留筛选、选择和位置。加载失败保留可用列表；解析失败提供真实可用处理入口。

教学文件、备课本和讲义各自保留已有用途与编辑流程；长标题可读，保存和预览明确，未保存输入受保护。不将教学文件强行重新定义为教学工作台首页。

## 题本与组卷

继承已批准组卷 V3：完整题目在主区，选题 / 题篮 / 编辑 / 预览共用同一题组。题干、选项、图像、公式、来源和状态清楚可读；筛选作为辅助，不挤占全部主区。

章节、题型、难度、来源和搜索沿真实能力实现，命中数及选择反馈一致。已加入和未加入可辨，重复加入受原规则限制。切换 / 返回保留题组与筛选；不能靠重新取全量数据清空教师选择。

一题的动作与整卷的动作区分。核对状态和来源改变使核对失效的规则不变；导出前保留原确认要求。模型或题库缺题时说明缺口，不暗改条件。

PPT 入口沿现有教学成果能力定位。对话到成果、已有编辑 / 预览 / 导出和返回的路径必须真实；本轮不建设新的 PPT 引擎。

## 学生工作台及子页

先选学生，再进入档案、查找记录、添加记录、错题练习、学习计划、复盘和概览。固定显示当前学生身份，切子页沿同一 studentId。切学生时保护草稿；旧请求晚返回不能覆盖新学生。

这些页面检查排版、状态、控件与主动作，保持既有业务范围；不引入学生端、家长端或学校管理模块。测试用虚构学生数据，不能用真实学生隐私当截图样例。

## 排版与状态约定

- 应用界面约 15px、正文约 16px，中文无衬线，沿现有设计 token；原文件 / Office 预览保持其字体。标题层次不超过页面 / 分组 / 对象所需层级。
- 容器负责一次布局内边距；避免双重套壳和重复卡片。宽屏保持合理阅读宽度，列表 / 编辑器利用剩余宽度。
- 长英文文件名、长中文、数字、标签和日期不能互相覆盖。主操作不因内容变长被挤出。
- 主要容器各有清楚滚动责任；固定顶部 / 底部不遮住获得焦点的字段。
- 无数据、筛选无结果、读取失败、无权限、处理中、部分成功使用不同的文案和动作，按实际功能适用。
