# 09 有限闭环与停止协议

## 核心定义

有限的是范围、验收集合和终态；不限的是为解决真实范围内问题所必需的正常修复轮数。本包明确替代旧 D15 / UI_FINAL_IMPLEMENTATION_GOAL 中每阶段最多两轮的上限。

## 执行状态

审计基线 → 冻结集合 → 实施 → 验证 → 交付。验证失败可回实施；必要依赖不可自行解除时完成独立部分后进入 BLOCKED。

对外 UI_R1_DONE 对应 delivery.json 的 DONE；只有它表示本轮通过。BLOCKED 表示本轮未通过且已有限收尾；NOT_RUN / FAIL 不是通过；文档写完也不是产品完成。

## 什么工作允许进入下一轮

1. 当前必选验收失败所需的最小必要修复。
2. 本轮修改引入的回归。
3. 冻结页面内新复现、会阻断教师操作或违反保护约束的问题。

新主题、新首页重构、无依据“更高级”、无关抽象 / 优化、扩大业务边界不进入剩余工作集合。已通过且未受新代码影响的项不反复美化。

## 每轮记录与有效进展

缺陷 ID → 关联验收 → 复现 / 输入 / 环境 → 当前证据 → 可检验假设 → 必要改动 → 验证结果。

有效进展包括：失败项转通过；根因或复现条件获得新证据；失败范围可验证缩小；解除真实依赖。单纯多写代码、换名称、重新截图、反复运行相同命令不构成进展。

连续两次相同输入、代码和环境产生相同失败且无新增信息，不得第三次照搬。下一步必须是新的有根据诊断、最小复现、改变确切条件或登记不可自行解除的阻塞。网络瞬断可以诊断性重试，但不能用无限重试掩盖访问 / 环境问题。这不是总修复轮数限制。

发现真实进展后继续修复不限次数；不得把某次研究或失败自动当作必须停工。能够独立推进的范围继续做完。

## DONE 判据

- UIR1-01 至 UIR1-28 全 PASS，证据对应最终有效运行代码。
- 本轮受影响 / 保护性旧门禁完成，既有其他缺口单独保留真实状态。
- 无 OPEN 或 DEFERRED 的本轮 S0 / S1 / S2 缺陷，不能降级绕过。
- 并行协作改动已安全整合，远端包含交付提交，供用户验收的实际窗口可见且可操作。
- 报告、命令、前后证据、readback、遗留、恢复和回滚齐全。

满足后立即完成收尾并停止。S3 新偏好进 FOLLOW_UP，不重新打开本轮；新的用户指令可形成下一轮任务。

## BLOCKED 判据与收尾

必要接口 / Pro 资源的不可替代部分 / 运行权限 / 实机环境 / 协作归属等缺失，执行方已确认无法在当前授权内解除；或存在可复现的技术阻塞，证据表明下一步必须改变范围、获得外部条件或执行未获授权的操作。仅仅“修起来困难”、已经修改很多轮、耗时较长或尚未找到根因，不足以停止本可继续推进的范围内修复。

不要只写“没权限”或“工具坏了”。报告具体项、最小复现、失败证据、尝试方法、当前可交付内容、解除条件、负责边界和下一次从哪里恢复。外部条件没有变化就不要循环等待或重开同一任务。

对 BLOCKED 的完成是报告与现场移交完成，不是产品目标完成。不能把成功截图遮住未完成能力，不能删除必选项来结案。

## 教师试用与自动执行结束

工程 / 实机验收和教师主观试用分别记录。没有真实老师参与就标 NOT_RUN，不代替老师填写“满意”。工程门禁通过且交付齐全即可结束本轮 AI 执行，等待下一条反馈；不能把“直到老师完全满意”作为无限运行条件。

若教师反馈已明确暴露必选失败，将其作为真实缺陷修复；单纯尚未收到反馈不阻止工程报告形成。

## 恢复与回滚

templates/EXECUTION_STATE.md 只保留最新阶段、当前问题、已验证证据、代码 / 构建身份、阻塞与下一步。不要为每一轮另起规划文档。

回滚按本轮可审查提交集合和依赖说明；共享 main 使用正常 revert 评审路径，不强推或 reset；不修改 / 删除真实用户数据以恢复 UI。
