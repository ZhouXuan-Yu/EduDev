# 05 并行协作与配置接口

## 责任分工

| UI R1 执行方 | 配置 / 底座原负责方 |
| --- | --- |
| 页面编排、教师文案、视觉状态、控件复用、局部前端状态和真实入口连接 | 配置 schema、模型连接、权限判定、记忆、任务 / 恢复、数据库与持久化事实 |
| 使用已存在 typed preload / IPC；检查真实响应与回读 | 实现 / 修改宿主接口及语义，提供版本和行为说明 |
| 记录接口缺口，显示准确限制或失败反馈 | 解除接口能力缺口，维护旧数据与兼容性 |

本包不授权通过邮件 / Slack 等对外发消息。协作信息优先写入共享工程记录和既有任务渠道，不要求用户反复做普通文件中转。

## 开工检查

记录 git status、工作树列表、当前分支和修改归属。重叠文件或服务正在修改时优先建立隔离工作树 / 最小独立组件，避免覆盖。不能执行 checkout --、reset --hard、清理他人未提交内容、强推或重装依赖来消除冲突。

共享设置组件的合并依据是实际接口行为，不是某个截图。如果另一位 AI 已完成修改，复核并复用，不再平行造相同配置页。

## 必须写清楚的接口字段

templates/CONFIG_CONTRACT.csv 每行一个实际设置 / 动作，记录：当前接口、值类型 / 枚举、scope、读取、保存、失败格式、生效时间、脏状态 / 取消行为、是否敏感、负责文件 / 任务、UI 文案和验证证据。

至少核对教学偏好、记忆、应用界面偏好、当前会话目录、文件权限、模型连接、备份 / 数据管理、扩展 / 能力状态等实际存在项。没实现的字段不得造默认值假装可用。

## 不可合并的语义

- 应用默认值不等于当前会话覆盖。
- 关闭记忆不等于删除记忆。
- 已授权目录不等于任意目录可读写。
- 接受编辑、自动批准、完全访问不是同一布尔开关。
- 点击保存不等于保存成功；保存成功不必然等于本轮已生效。
- 查询失败不等于没有设置 / 没有偏好。

教师文案可以简化，但实际选择的后果必须说明。

## 依赖阻塞时

记录需要的接口 / 行为、当前 SHA、最小复现、期望与实际、归属、解除条件；完成其他可独立的 UI 修复。已有失败保持可见，界面提供真实可用的返回 / 重试入口。

不能创建临时 SQLite 表、另一个权限判断器、前端假任务、固定生成结果来“让验收通过”。必要集成未完成，则本轮明确 BLOCKED；不用无限等待另一 AI。

## 合并与回归

整合前刷新 origin/main，检查重叠变更，按仓库既有授权普通合并与 push。远端前进时验证交付提交被包含，不要求远端永远停留在该 SHA。

若整合改动了实际运行代码，重新构建并复验受影响项；只有证据 / 文档新增时可保留原实机证据，必须有差异清单证明代码未变化。记录最终源代码、构建身份、窗口与远端包含关系。
