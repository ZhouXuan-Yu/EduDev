## 证据与状态

- PASS：达到该项全部判据，证据可定位且来自适用有效构建。
- FAIL：已执行且有具体未满足项，必须关联缺陷。
- BLOCKED：必要外部条件缺失，记录条件与解除方式。
- NOT_RUN：尚未执行，绝不是通过。

每项可引用多份共享证据，但写清楚证明的行为。最低证据层表示必须具备该类证据，不表示仅一张该类截图就足够。

static：范围、代码 / CSS 审计或报告；component：组件 / 契约测试；electron：真实桌面操作；readback：实际宿主读回、数据库 / 文件结果；git：提交 / diff / 远端关系；measurement：带原始样本的性能记录。

fixture-only、模拟 provider、静态网页与真实 provider 分别标注；不得用前者代替本表要求的真实集成。真实生成触发用户已有服务和授权，受阻则记录。

本表 18 页覆盖和本项目时延目标是工程约定，不是引用外部规范的原文。教师视觉接受单独记录，工程 PASS 不冒称用户已经满意。

只在 28 项全部 PASS、必需旧行为回归成立、无未关闭范围内 S0/S1/S2、真实交付窗口与代码一致时，输出 UI_R1_DONE。未达到时输出 BLOCKED 并保留每项状态。不得因为任务运行很久或修复次数很多而把失败改通过。
