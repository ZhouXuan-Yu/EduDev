阶段有明确产出，不设置总修复次数。每阶段的 UI 缺陷修复和相关复验可以继续到达标；硬依赖则转有限阻塞收尾。

| --- | --- | --- |

## P0 读取顺序

根 AGENTS / 2.Memory / Master 及状态 → renderer AGENTS → edudev-design 及台账 → 当前设计交接 / 页合同 → 实际运行 / 源码 / 相关测试 → 本包范围表与任务清单。

发现旧轮次上限时，记录本轮用户指令与覆盖范围；不回退为两轮就放弃。发现未批准新页面方案，不自动实装，也不影响当前修复。

## 实施规则

- 一个切片对应一个可验收结果，例如设置导航不再混淆、任务卡片真实行动可见；别以“改了多少 CSS”计进展。
- 先验证能否使用现有 wrapper 修复，再改变多页调用；避免新增同功能组件和大量兼容层。
- 多文件修改可以按关联一起处理；不推倒重写，不顺带升级，不把所有逻辑继续堆 App.tsx。
- UI 异步读取使用当前对象身份防止迟到污染；UI 适配可修复，但底层状态机变化属于配置 / Harness 接口问题。
- 删除旧展示规则前证明新入口真实可用，记录旧功能去向，保留测试覆盖与可回滚提交。

## 回归范围

局部文字 / 间距不必每次跑全库。组件替换验证自身状态与所有受影响消费者；共享 CSS、导航、输入、保存 / 对象身份变化需要对应跨页回归。最终执行仓库要求和本包必选门禁。

最终测试后再改运行代码或合并代码，原相关证据失效，需要重新验证；文档改动用 diff 证明无需重跑应用。重复运行必须解决具体风险，不能把重复测试本身当进度。
